Embeddings

Giving a token a list of learned numbers, so that similar tokens get similar lists

A token's ID is only a name. A language model needs numbers that say something about the token, so it looks up a row of learned numbers for the ID. That row is an embedding. This chapter shows how the table of rows works and why a lookup is enough. It compares words with cosine similarity, draws a map of 50-number GloVe vectors for sea, Mumbai and SharkCam words, and tests the famous analogies, including one that fails.

The last section embeds whole messages in four languages. All sixteen messages are invented, and the Hindi, Marathi and Hinglish texts have not yet been checked by a native speaker.

You will need: tokens and IDs (D1), the dot product and cosine similarity (0.5) and a matrix as rows (0.5).

One-hot vectors and the lookup table

Guess first. The token “▁shark” has ID 21027 in GPT-2. Could the model feed that number into a layer, like a length or a weight? And if instead the 50,257 tokens had an input slot of their own, all zero except one, how many multiplications would one token need in a layer with 768 outputs?

embedding
the list of \(d\) learned numbers that represents one token
embedding table \(E\)
a matrix with one row per token and \(d\) columns
one-hot vector
a vector of zeros with a single 1 at the place of the token's ID
dimension \(d\)
how many numbers an embedding has (GPT-2 small: 768)

An embedding table is a matrix with one row per token. Multiplying a one-hot vector by it picks out one row, so a model simply copies that row.

For the toy table, multiplying costs 32 products and 28 of them are with a zero. For GPT-2 the same trick would cost 38.6 million products, against 768 copies for the lookup. The numbers in the toy table are made up.

Pick a word. The coral 1 in the one-hot vector multiplies its own row of the table, and all the zeros wipe out the other rows. The result is that row. Click a number of the result to see the sum behind it. A table lookup does the same job without any arithmetic. The model never uses the ID as a quantity, because an ID has no meaning (D1). It uses the ID as an address.

The rows of the table are parameters, learned like any weights by gradient descent (B3). Press the training nudge. It applies one update to the row you selected, with a made-up slope of the loss and a step size of 0.5. The row of “dolphin” moves from (0.70, −0.40, 0.80, 0.20) to (0.50, −0.30, 0.75, 0.05), and no other row changes. The reason is the outer product of 0.5 and the backward pass of B4. The slope of the table is a one-hot vector times the slope at the embedding. So only the row of a token that was used gets a nonzero slope. A rare token's row learns rarely, which is why embeddings of rare words are poor.

50,257 × 768rows × numbers per row=38,597,376numbers in GPT-2's table÷124,439,808parameters in GPT-2 small=31%of the model

\[ \mathbf{e}_i \;=\; \mathbf{o}_i^{\top} E \;=\; E_{i,:} \qquad\qquad \frac{\partial L}{\partial E} \;=\; \mathbf{o}_i \left(\frac{\partial L}{\partial \mathbf{e}_i}\right)^{\!\top} \]

  • \(E\) is the embedding table with \(V\) rows (the vocabulary size) and \(d\) columns. \(\mathbf{o}_i\) is the one-hot vector of the token with ID \(i\), and \(\mathbf{e}_i\) is its embedding.
  • \(E_{i,:}\) means row \(i\) of \(E\). The table has \(V \times d\) numbers.
  • The right-hand formula says the slope is zero in all rows except row \(i\), where it equals the slope at the embedding (\(L\) is the loss, B3).

In GPT-2 small the table is a third of the model. Radford and colleagues (2019) list the width \(d\) of their four models as 768, 1,024, 1,280 and 1,600. The same table is also used in the other direction at the end of the network, where it scores the tokens (D3).

import numpy as np

words = ["shark", "whale", "dolphin", "boat", "net", "dock", "camera", "tide"]
rng = np.random.default_rng(4127)
E = rng.normal(0, 0.5, size=(len(words), 4)).round(2)   # the table: one row per word, random start

i = words.index("dolphin")
one_hot = np.eye(len(words))[i]          # 8 numbers, a single 1
print(one_hot)
print(one_hot @ E)                       # eight products per number...
print(E[i])                              # ...or just copy the row
print(np.allclose(one_hot @ E, E[i]))

grad_e = np.array([0.4, -0.2, 0.1, 0.3]) # made-up slope of the loss at the embedding
E[i] -= 0.5 * grad_e                     # one update: only this row moves
print(E[i])

Common belief. The one-hot vector of a word, or its ID, already tells the model what the word means.

Why it fails. In one-hot form all words are at the same distance from one another. The cosine of two different one-hot vectors is 0, so “shark” is as far from “whale” as from “tide”.

Better account. The rows of the table are learned, so that tokens used in similar ways end up with similar rows.

Debug tip. If a lookup fails with an index error such as “index out of range in self” in PyTorch, an ID is at least as large as the number of rows. The text was tokenised with a different tokenizer than the model's. If the sizes happen to fit, there is no error at all, only wrong output.

Used in: the first layer of all language models (D5), and the next section, which asks where the numbers come from.

Quick quiz

A batch has three tokens, two of them the same. How many rows of the table get a slope?

Two. The repeated token's row gets the slopes of both positions added together, and all other rows get none.

Why is a lookup the same as a matrix product with a one-hot vector?

The vector has a 1 at one place and 0 elsewhere, so all products with the other rows are 0 and the sum is the chosen row.

A word and its company

Guess first. In the 24 short sentences below, “shark” and “whale” never appear together, while “camera” and “lens” often do. Which pair would you call more alike in meaning, using only the words around them?

context
the other words in the same sentence
count vector
a word's row of counts: how often a context word appears with it
cosine similarity
\(\cos\theta = \dfrac{\mathbf{u}\cdot\mathbf{v}}{\|\mathbf{u}\|\,\|\mathbf{v}\|}\), the similarity of direction (0.5)

Words that keep similar company get similar count rows, and the cosine of two rows measures how alike they are. Learned embeddings are a short, dense version of the same idea.

Counts: sentences in which the row word and the column word appear together (made up)

Cosine of all pairs of rows (click a cell)

Shark, whale and dolphin have cosines of 0.83 to 0.89 with one another, though no sentence has two of them. Camera and lens, which appear together, score only 0.17. The sentences are made up for this chapter.

Click the row of “shark”, then the row of “whale”. Both rows have counts under “sea”, “fin”, “reef” and “swam”. The dot product adds up the products of matching counts. The cosine divides by the lengths, so a word seen often does not win just by having bigger counts. The working is in the boxes. For the second case, take “boat” and “trawler”: they share “dock”, “net” and “harbour”, and the cosine is 0.71. “Camera” and “lens” are one another's context, so they do not share context words, and their rows barely overlap.

Large corpora have millions of different context words, so these rows would be very long and mostly zeros. Embedding methods compress them into short dense rows. Word2vec learns its vectors by predicting which words appear near one another (Alammar, 2019). GloVe, used in the next section, was fitted to co-occurrence statistics of 6 billion words of Wikipedia and Gigaword text (Pennington, Socher and Manning, 2014). The language model of D3 learns its embeddings as part of predicting the next token.

Common belief. Words that appear together are similar in meaning.

Why it fails. “Camera” and “lens” appear together in this corpus and have a low cosine. “Shark” and “whale” never meet and have a high one.

Better account. Words are similar when they appear in similar contexts. Words that go together are related, which is a different thing.

Debug tip. A word seen only once or twice has a noisy row, so its neighbours can look odd. Before you trust a neighbour list, check how often the word occurs in the data.

Used in: choosing which embeddings to trust (next section), and the training objective of D3.

Quick quiz

Two rows are (2, 0, 1) and (4, 0, 2). What is their cosine?

The cosine is 1. The second row is twice the first, so the directions are the same. The dot product is 10, and the lengths are 2.236 and 4.472, which multiply to 10.

Why divide by the lengths?

A word that occurs ten times as often has counts ten times as large. The cosine keeps only the direction, so frequency does not decide the score.

A map of words

Guess first. The words below are rows of 50 numbers learned from Wikipedia and news text. The word “net” appears in fishing, but also in “net profit”. Will its nearest neighbours be “boat”, “camera” or “price”?

GloVe
word vectors learned from word counts; this chapter uses the 50-number version (PDDL licence)
projection
squashing 50 numbers per word down to 2, so that a picture is possible
t-SNE and PCA
two ways to project: t-SNE tries to keep close words close, PCA keeps the two directions with the most spread
nearest neighbour
the word with the highest cosine to a given word

Words with similar neighbours get similar rows, so related words appear near one another on the map. The map is a flattened view, so the cosine of the 50 numbers is the actual measure.

Shark appears among the sea animals, with dolphin (0.85) and whale (0.83) as nearest neighbours, and Mumbai appears among other South Asian cities such as Bombay, Karachi and Delhi. A dotted line joins the chosen word to its five nearest neighbours in 50 numbers. The map is computed offline from GloVe (Pennington, Socher and Manning, 2014).

Click words and compare. “Net” is nearest to price, market and data among the 76 words, and among all 400,000 words its neighbours are profit, quarter and revenue. The text GloVe learned from used “net” more for money than for fishing, and a table has only one row per word, so the senses are blended. “Tag” is near “card”, “ring” and wrestling. The word “spadenose” has no row at all, since the word is missing from the 400,000 words. That is the unknown-word problem of D1: a word-level table cannot embed a word it never met, and a table of subword pieces can.

Switch between the t-SNE and PCA maps and the layout changes a lot, which says something. Fifty numbers cannot be drawn faithfully in two. PCA's two axes capture only 33% of the variation in these 76 words. A standard score asks how well a map's neighbours are also neighbours in 50 numbers. It is called trustworthiness, and 1 is perfect. At five neighbours it is 0.965 for t-SNE and 0.847 for PCA. t-SNE is better at neighbourhoods. Its cluster sizes and the gaps between clusters mean little, though, and a different setting of its perplexity can give a different picture (Wattenberg, Viégas and Johnson, 2016). The status line under the map tells you when the nearest word on the map and the nearest word in 50 numbers differ.

\[ \cos\theta \;=\; \frac{\mathbf{u}\cdot\mathbf{v}}{\|\mathbf{u}\|\,\|\mathbf{v}\|} \;=\; \frac{\sum_{j=1}^{50} u_j v_j}{\sqrt{\sum_j u_j^2}\;\sqrt{\sum_j v_j^2}} \]

  • \(\mathbf{u}\) and \(\mathbf{v}\) are the 50-number rows of two words, and \(u_j\) is the \(j\)-th number. The boxes above the map show the dot product, the two lengths and the cosine.
  • For “shark” and “whale” the dot product is 22.27 and the lengths are 5.01 and 5.33, so \(\cos\theta = 22.27/(5.01\times 5.33) = 0.83\). For “shark” and “camera” it is only 0.17.

Common belief. A word has one vector, so a word has one meaning for the model.

Why it fails. Look at “net” and “tag”. Their single rows blend the senses, and the finance and wrestling senses dominate.

Better account. Inside a transformer, the row from the table is only the starting point. Attention mixes in the other words of the sentence, so the same token gets different vectors in different contexts (D4).

Analogy. A flat map of the Earth. It shows which places are close, though it stretches the far north.

Where it breaks. A globe loses one dimension when flattened. This map loses 48. Neighbours on the map can be far apart in 50 numbers, and the distances across the map mean little.

import json, numpy as np

D = json.load(open("words.json"))
allw = D["words"] + D["extra"]                       # 104 words, 50 numbers per word
names = [w["w"] for w in allw]
V = np.array([w["v"] for w in allw])
U = V / np.linalg.norm(V, axis=1, keepdims=True)     # unit length: a dot product is now a cosine

def nearest(word, k=5):
    s = U @ U[names.index(word)]
    order = [j for j in np.argsort(-s) if names[j] != word][:k]
    return [(names[j], round(float(s[j]), 2)) for j in order]

print(nearest("shark"))
print(nearest("mumbai"))
print(nearest("net"))

Quick quiz

The map shows “boat” right next to “net”. Can you conclude their rows are very similar?

No. Check the cosine of the 50 numbers. The map may have pulled two words together that are far apart in 50 numbers.

Why can GPT-2's table embed “spadenose” while GloVe cannot?

GPT-2 cuts the word into subword pieces such as “▁sp”, “aden” and “ose”, and the pieces have rows of their own. GloVe needs the whole word in its list.

Directions and analogies

Guess first. Take the 50 numbers of “king”, subtract those of “man” and add those of “woman”. Which word has the row nearest to the result? And would the same trick turn “fish” into “bird”, if you take away “scale” and add “feather”?

offset
the difference between two embeddings, such as \(\mathbf{v}_{\text{king}} - \mathbf{v}_{\text{man}}\)
analogy
“A is to B as C is to ?”
answer
the word whose row has the highest cosine with the result vector

The difference between two related words often points in a similar direction for other pairs, so \(\mathbf{v}_A - \mathbf{v}_B + \mathbf{v}_C\) can fall near the word that completes an analogy. It works for some relations and fails for others.

King − man + woman gives queen at 0.86. Over all 400,000 words, fish − scale + feather gives trout at 0.75, though the expected answer is bird. The figure searches 104 words. The notes below a preset give the result over all 400,000 words.

Press the preset buttons one by one. The first four work or half work. In the fifth, Mumbai − India + Japan gives Tokyo, with a caveat: Mumbai is India's largest city and not its capital, and Tokyo is both for Japan.

The sixth fails. A fish has scales as a bird has feathers, so the answer should be “bird”. The nearest words are trout, herring and salmon, and “bird” comes 248th of 400,000. The result stays close to “fish”. The arithmetic finds the neighbourhood of an input and misses the relation. One reason is that “scale” mostly appears in text about size, as in “the scale of the damage”. Its row blends two senses, like “net” and “tag” on the map.

The last preset is a warning. “Doctor” − “man” + “woman” gives “nurse”. This looks like a success and is a learned bias. Word vectors are learned from text that people wrote, so they copy the patterns in that text, including stereotypes. Bolukbasi and colleagues (2016) tested word2vec vectors learned from Google News articles. The vectors completed “father is to doctor as mother is to” with “nurse”, and “man is to computer programmer as woman is to” with “homemaker”. The GloVe vectors here come from Wikipedia and news text, and give the same “nurse” answer. The vectors record how people wrote. They do not show who can be a doctor or a nurse. A system that ranks people or messages with such vectors can repeat the bias, and checking for it is part of F1.

Tick off “leave out the three input words” to see a problem of the method: with the inputs allowed, the nearest word is often the input itself. Standard tests leave them out. Linzen (2016) shows that the method's use of cosine similarity mixes the offset with the neighbourhood of the inputs.

v(king)start−v(man)take away+v(woman)add=qa vector, not yet a word→queen 0.86the word with the highest cosine to q

\[ \mathbf{q} \;=\; \mathbf{v}_A - \mathbf{v}_B + \mathbf{v}_C \qquad\qquad \text{answer} \;=\; \operatorname*{arg\,max}_{w \,\notin\, \{A,B,C\}} \; \cos(\mathbf{v}_w, \mathbf{q}) \]

  • \(\mathbf{v}_A\), \(\mathbf{v}_B\), \(\mathbf{v}_C\) are the 50-number rows of the three input words, and \(\mathbf{q}\) is the result of the arithmetic.
  • \(\cos(\mathbf{v}_w, \mathbf{q})\) is the cosine of a candidate word's row with \(\mathbf{q}\) (0.5). The word with the largest value is the answer, and the three inputs are left out.

How often does the method find the expected word? The chart below uses the analogy test of Mikolov and colleagues (2013), which ships with the gensim library. Only the 14,877 questions whose words are all among GloVe's 30,000 most frequent words were asked, and the top answer was right 50% of the time. The score depends strongly on the relation. It is 94% for nationality adjectives and 80% for capitals of common countries. It is only 16% for cities in US states (the coral bar), where one state has many cities, and 13% for currencies. Many cities share a state, and many words share a nearest neighbourhood, so a single offset cannot choose.

The arithmetic is right half the time overall, and nearly never for currencies and for cities in US states. The dotted line is the overall score of 50%. Computed for this chapter with gensim's evaluate_word_analogies.

Common belief. Embeddings store meaning as arithmetic, so the model understands that king is man's royal form.

Why it fails. The method is right half the time on a standard test, depends on leaving the inputs out, and fails for one-to-many relations. It also reproduces stereotypes from its text, as the doctor and nurse preset shows.

Better account. Embeddings contain statistics of how words are used. Some directions line up with simple relations. Treat an analogy as a probe of the table. It does not show understanding.

Debug tip. If an analogy returns one of its three inputs, leave the inputs out of the search before you conclude anything. If it returns something odd, check the neighbours of the inputs one at a time first.

Used in: the way a retrieval system finds related words, and as a quick test of a new embedding table. A deeper question for a SharkCam reader of messages is in the exercises.

Quick quiz

Why must the search leave out “king”, “man” and “woman”?

The result \(\mathbf{q}\) is close to the input words, because the offset is small compared with the word vectors. With the inputs allowed, the nearest word is often “king” itself, at 0.89.

The test gives 16% for cities in US states. What does that say about using the method on SharkCam's places?

One-to-many relations are hard, so Mumbai, Versova and Uran, which all belong to Maharashtra, will not be handled by one offset.

From words to sentences

Guess first. Message m02 (English) and message m10 (Marathi) report the same find, Tag 4127. They share almost no words and use different scripts. Will a model place them close together or far apart?

sentence encoder
a model that turns a whole text into one vector
multilingual
trained on many languages, so that texts with the same meaning fall near one another

A multilingual sentence encoder places texts with the same meaning near one another even across languages. It does this less well for some languages and some messages.

Messages on the same topic have a mean cosine of 0.61, against 0.42 for different topics. The nearest message shares the topic for 13 of the 16. The model is paraphrase-multilingual-MiniLM-L12-v2 (384 numbers per text, Apache-2.0 licence). Its two-dimensional PCA map keeps 40% of the variation.

Check before reuse. All sixteen messages are invented, and the Hindi, Marathi and Hinglish texts have not yet been checked by a native speaker. Sixteen texts are a tiny sample. Messages on one topic also share numbers (44, 4127, 80), which an encoder may use as a cue.

Click a message. For Tag 4127, the Hindi message m06 and the Marathi message m10 have a cosine of 0.92, and the English message m02 is 0.83 from m10. That answers the guess. The weak spots matter as well: the Marathi message m11 about the young hammerhead has its nearest neighbour at only 0.63. The encoder was trained on 50 or more languages, which include Hindi and Marathi (Reimers and Gurevych, 2020). Quality can differ between languages, and no quality figure for Hindi or Marathi was found. In D1 the same messages cost five times as many tokens in Hindi. The encoder shows that the meaning can still arrive in the same neighbourhood.

Common belief. If a model puts a Hindi and a Marathi message close together, it reads both languages well.

Why it fails. A high cosine says that two vectors point the same way. Shared topic words and shared numbers (44, 4127, 80) can cause that. For m11 the nearest message has a cosine of only 0.63.

Better account. A multilingual encoder finds likely matches. A person or a second test must check them.

This is the idea behind searching messages by meaning, grouping reports by topic, and, in E2, placing a photo and its caption in one space.

Quick quiz

Does a cosine of 0.92 between a Hindi and a Marathi message mean they say the same thing?

No. It says that their vectors point in nearly the same direction. They share a topic and several numbers. Check the texts before concluding that they match.

Exercises

Theory

  1. theory GPT-2 has \(V = 50{,}257\) tokens and \(d = 768\). (a) How many numbers are in its table? (b) What share of GPT-2 small's 124,439,808 parameters is that? (c) How many multiplications would a one-hot product need for one token, and how many copies does a lookup need?

  2. theory In the toy table of the figure, shark = (0.9, −0.3, 0.7, 0.1), whale = (0.8, −0.2, 0.9, 0.0) and boat = (−0.5, 0.8, 0.1, 0.6). Compute the cosine of shark with whale and of shark with boat by hand. What do the signs say?

    Hint

    Dot product first, then the two lengths.

  3. theory One training step on the token “boat” has a slope of the loss at its embedding of (0.2, −0.4, 0.0, 0.6). With a step size of 0.5, compute the new row. Which other rows change? Explain with the outer product.

  4. theory In two dimensions let man = (1, 1), woman = (1, 3), king = (4, 1) and queen = (4, 3). Compute king − man + woman and find the nearest word by cosine. Then move king to (4, 2) and repeat. What does the result say about what the method needs from the data?

Think deeper

  1. open “Doctor” − “man” + “woman” gives “nurse”. SharkCam's message reader will use an embedding table. What would you measure to check it for bias, and what would you do if you found some? What could go wrong with these fixes?

Come back later

Try these after two days, and again after a week, without looking back.

A tokenizer cuts “sharkcamera” into “▁shark” and “camera”. How many rows of the embedding table does the model use for it? (Chapter D1)

Two, one per piece. The table has a row per token, and a word that is cut into pieces has no row of its own.

The vectors (2, 1) and (4, 2) are two embeddings. What are their dot product and cosine? (Chapter 0.5)

The dot product is \(2\cdot4 + 1\cdot2 = 10\). The cosine is 1, since both point the same way. Only the lengths differ.

A training batch has the tokens “shark”, “at” and “dock”. Which rows of the table get a slope, and what kind of matrix is that slope in B4's terms? (Chapter B4)

Three rows. The slope of the table is a sum of outer products of one-hot vectors with the slopes at the embeddings, so it is zero in all other rows.
