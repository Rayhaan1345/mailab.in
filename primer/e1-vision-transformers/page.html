A language model reads tokens (D1). A vision transformer (ViT) reads a photo the same way, once the photo is cut into square patches and the patches are turned into vectors. This chapter cuts a shark photo with a slider and computes a patch token from the numbers of a trained network. It then shows what the position embeddings and the class token do. You then click a patch to see where it looks, compare what a CNN and a ViT can reach, and replace patches by entries of a code book.

The network is torchvision's ViT-B/16 with ImageNet weights, run offline on photos of sharks, so its calls on shark species are often wrong, and the chapter says so. The code books are made with k-means on small patches. {{snippet:photos-credited-under}}

You will need: the transformer block and attention (D5, D4), the embedding table (D2), filters and receptive fields (C1, C2), and matrix products (0.5).

Cutting a photo into patches

Guess first. A photo of 224 by 224 pixels has 50,176 pixels. If one pixel were one token, attention would compare all tokens with one another, as in D4. How many pairs is that? What could you use as a token instead?

patch
a square block of P by P pixels cut from the photo; the token of a ViT starts as one patch
patch side P
the side of a patch in pixels; ViT-B/16 means the base-size ViT with P = 16
sequence length
the number of tokens the transformer reads; attention costs grow with its square (0.2)
vision transformer (ViT)
a transformer (D5) whose tokens are patches

A ViT reads a photo as a short row of patches, so that attention compares a few hundred tokens and not tens of thousands of pixels.

Halving the patch side gives four times as many patches and about sixteen times as many attention pairs. The photo is the same, and the count of numbers in it is the same: 224 × 224 × 3 = 150,528 for any patch size.

Move the slider, then press Step or Play. A patch is lifted from the grid into the row, and its position number appears below it. The numbers run in reading order, from the left of the top row to the right of the bottom row. The row shows the first nine tokens and the last, because 196 tokens do not fit on a screen. Tick the box and the class token takes position 0 (the class token section explains it).

A worked case with P = 16. The photo has 224 pixels on a side, so 224 / 16 = 14 patches fit across and 14 down. That gives N = 14 × 14 = 196 patches. A patch has 16 × 16 pixels with three colours, so 768 numbers. Add the class token and the sequence has 197 tokens, so one head of attention scores 197 × 197 = 38,809 pairs. With one pixel per token the sequence has 50,176 tokens and 2,517,630,976 pairs, about 65,000 times more.

A second case, P = 8. Now N = 28 × 28 = 784 patches of 192 numbers. The sequence has 785 tokens and 616,225 pairs, which is 15.9 times the cost of P = 16. The cut loses no numbers, since 784 × 192 is again 150,528. What changes is how much the later blocks must handle.

224 / 16patches across, S / P×224 / 16patches down=196patches, N|197²pairs per head, (N + 1)²

\[ N = \frac{S}{P}\cdot\frac{S}{P} = \frac{S^2}{P^2},\qquad \text{numbers per patch} = P^2 C,\qquad n = N + 1,\qquad \text{pairs per head} = n^2 \]

  • \(S\) is the side of the photo in pixels (224 here, a square photo) and \(P\) the side of a patch. \(C\) is the number of colour channels, 3 (C1).
  • \(N\) is the number of patches. \(n\) is the sequence length with the class token added; \(n\) matches the symbol of D4, where attention costs grow like \(n^2\).

Why this works, and where it is crude. A patch of 16 pixels is cut with no regard to what is in it, so a fin can be split over four patches. The transformer must put it together again, and attention is the tool that does so. A small animal is a problem. A shark 60 pixels long in a photo 640 pixels wide is about 20 pixels long after the photo is resized to 224. It fills little more than one patch. The name of a model tells you its cost. ViT-B/32 has 49 patches and ViT-B/16 has 196, and the second does about four times the work (the count is in ViT against CNN).

Common belief. Smaller patches always give a better view of the shark, so use the smallest.

Why it fails. Cost grows with the square of N. From P = 16 to P = 8 the pairs grow 15.9 times, and a patch of 8 by 8 pixels has only 192 numbers. That is little to say about a fin by itself.

Better account. The patch side trades detail against cost. The ViT paper (Dosovitskiy and others, 2021) notes that smaller patches cost more computation, and the choice of P is made for the budget at hand.

Debug tip. When you cut a photo with NumPy, check the order of the axes. img.reshape(196, 768) on its own gives stripes of 4 rows, not patches. The cut needs a reshape into (14, 16, 14, 16, 3), a transpose of the middle axes, and then a reshape. Test it: patch 1 must equal img[0:16, 16:32].

import numpy as np
S, P, C = 224, 16, 3
img = np.arange(S * S * C).reshape(S, S, C) % 251     # a made-up picture, values 0 to 250
g = S // P
patches = img.reshape(g, P, g, P, C).transpose(0, 2, 1, 3, 4).reshape(g * g, P * P * C)
print(patches.shape)
print(np.array_equal(patches[1], img[0:16, 16:32].reshape(-1)))
print(patches.size == img.size)
for P in (8, 16, 32):
    N = (S // P) ** 2
    print(P, N, N + 1, (N + 1) ** 2)

Quick quiz

How many patches does a 224 by 224 photo give with P = 32, and how many numbers does a patch have?

Since 224 / 32 = 7, there are 49 patches. A patch has 32 × 32 × 3 = 3,072 numbers. The total is 49 × 3,072 = 150,528, as before.

Why does attention over patches cost about 16 times more when P goes from 16 to 8?

N grows four times, since both the number across and the number down double. Attention compares all pairs, so its cost grows with the square of the sequence: 4 × 4 = 16, or 15.9 once the class token is counted.

From a patch to a token

Guess first. A patch of 16 by 16 pixels with three colours has 768 numbers. The vectors inside ViT-B/16 also have 768 numbers. Is the patch already the token, or does something still happen to it? If so, what is the simplest operation that could do it?

patch embedding
the vector a patch becomes, with d numbers (768 in ViT-B/16); the token the first block reads
linear projection
a matrix product plus a bias, \(W\mathbf{x} + \mathbf{b}\), the weighted sums of B1
model width d
the length of a token vector (D4); here 768
filter
a set of weights laid over a patch, as in C1; a row of the matrix is one

One matrix, the same for all patches, turns the 768 pixel numbers of a patch into 768 learned numbers. This is what a convolution with a 16 by 16 filter and a step of 16 does.

Click a patch (or use the arrow keys)

The patch, 16 by 16 pixels, and its 768 numbers laid out in 16 rows of 48 (three cells, red, green and blue, for a pixel)

Eight of the 768 rows of the matrix, drawn as colour pictures, multiplied with the patch numbers and added to a bias

Sizes for a patch side P (the live numbers above are for P = 16)

A token number is one dot product of the patch with one row, and the same 768 rows are used on all 196 patches. Teal numbers are positive and coral numbers negative. Some rows look smooth and some look like noise.

The numbers in the figure come from the first layer of torchvision's ViT-B/16. The page takes the pixels of the selected patch, scales them as the network expects (subtract the mean, divide by the spread of the colour). It then computes eight of the 768 dot products itself. The results agree with the network's own output to within 0.003. Try the patch in the water and then a patch on the body. The values change, and the network reads them as its first description of the patch.

Two worked cases for the hammerhead photo. The patch at grid row 6, column 6 lies on the body. Its eight numbers are 0.04, −0.05, −0.11, 0.09, −0.10, −0.30, 0.09 and 0.22. The patch in the top left corner is blue water. Its eight numbers are −0.09, 0.05, 0.16, −0.09, −0.03, 0.06, −0.04 and −0.02. The two sets differ, and the matrix has 760 more rows that the figure does not show.

768×1token e=768×768Wpatch, 589,824 weights×768×1x, the flat patch+768×1bias b

\[ \mathbf{e}_i = W_{\text{patch}}\,\mathbf{x}_i + \mathbf{b},\qquad W_{\text{patch}}\in\mathbb{R}^{d\times P^2C},\qquad \mathbf{x}_i\in\mathbb{R}^{P^2C} \]

  • \(\mathbf{x}_i\) is patch \(i\) flattened into a list of \(P^2C = 768\) numbers, row by row, three colours per pixel. \(\mathbf{e}_i\) is its embedding, with \(d = 768\) numbers.
  • \(W_{\text{patch}}\) has \(d\) rows and \(P^2C\) columns. Row \(j\) is a filter of 16 by 16 by 3 weights, and output number \(j\) is its dot product with the patch plus \(b_j\). The matrix and the bias are learned with the rest of the network (B4).
  • The count of learned numbers is \(d\,P^2C + d = 589{,}824 + 768 = 590{,}592\). In C1 terms, a convolution with 768 filters of 16 by 16 on 3 channels has \((16\cdot16\cdot3+1)\cdot768 = 590{,}592\) weights. With a step of 16 it gives \((224-16)/16+1 = 14\) positions across.

Why it works. The first block needs vectors, and a linear map is the plainest way to get them. It is cheap: one patch costs 589,824 multiply-adds, and the whole photo 115,605,504, the same for P = 8, 16 or 32, because a pixel number meets 768 weights once. The cost that depends on P comes later, in the blocks. Where it is limited. The matrix sees one patch at a time, so it cannot know about the neighbouring patch. All use of context is left to attention.

Analogy. The embedding table of D2: a token ID picks a row, and the row is its vector.

Where it breaks. A table has one row per known token. There is no table of patches, since there are 256768 possible patches. The matrix gives a vector to any patch, including one never seen, and patches with similar pixels get similar vectors. The matrix is a function and not a dictionary.

Debug tip. If a pretrained ViT returns confident nonsense on your own photo, print the mean and spread of the input after scaling. They should be near 0 and 1 for red, green and blue. A network trained on scaled pixels given values from 0 to 255 produces tokens a hundred times too large. Check also that the colour order is red, green, blue and not blue, green, red.

import numpy as np
rng = np.random.default_rng(4127)
img = rng.integers(0, 256, size=(224, 224, 3)).astype(float)
patches = img.reshape(14, 16, 14, 16, 3).transpose(0, 2, 1, 3, 4).reshape(196, 768)
W = rng.normal(0, 0.02, size=(768, 768))     # made-up weights: one row per output number
b = np.zeros(768)
tokens = patches @ W.T + b
print(tokens.shape, W.size + b.size)
w0 = W[0].reshape(16, 16, 3)                 # row 0 as a 16 by 16 by 3 filter
by_hand = (img[0:16, 16:32] * w0).sum() + b[0]
print(np.isclose(tokens[1, 0], by_hand))
print(768 * 768 * 196)

Quick quiz

With P = 32, how many columns does the patch matrix have, and how many weights?

A patch has 32 × 32 × 3 = 3,072 numbers, so the matrix has 3,072 columns and 768 rows: 2,359,296 weights, plus 768 biases. A larger patch gives a larger matrix and fewer tokens.

Why is the same matrix used for all patches?

So that a feature found in one part of the photo can be found in another, as with a filter that slides in C1. It also keeps the count of weights small: one matrix and not 196.

Position embeddings

Guess first. You cut a shark photo into patches and move all of them to other places. The ViT still gets all the patches, and the position vectors stay at their places. Does its answer change a little, or fall apart? What would a CNN do?

position embedding
a learned vector added to a patch token; row \(i\) of a table with \(N + 1\) rows says "this token is in place \(i\)"
permutation
a reordering of a list (0.4)
bag of patches
a model that uses what the patches contain and not where they are

Attention alone cannot tell where a patch came from, so a ViT adds a position vector to a token. In these photos, the trained ViT leans less on positions than a CNN leans on layout.

A. The position table of the trained ViT: click a position and see how similar the other 195 positions are to it

Photo (for orientation)

Cosine similarity of position embeddings

Positions that are close have similar embeddings, and positions in the same row or column are more alike than positions that merely share a distance. Nobody told the network this. It is the table that training produced.

Without a position vector, the model would treat the 196 patches as a set. This can be shown in two lines. Attention (D4) computes an output as a weighted sum of values, with weights from query-key dot products. If you reorder the input tokens, the same sums are formed from the same numbers. The outputs then come out reordered in the same way and are otherwise unchanged. The code below checks it. Adding a position vector breaks this symmetry: patch content moves, position vectors stay, and the outputs change.

\[ \mathbf{z}^{(0)}_i = \mathbf{e}_i + E_{\text{pos}}[i],\qquad E_{\text{pos}}\in\mathbb{R}^{(N+1)\times d} \]

  • \(\mathbf{z}^{(0)}_i\) is the input of token \(i\) to the first block. \(\mathbf{e}_i\) is its patch embedding from the last section.
  • \(E_{\text{pos}}\) is a table like the embedding table of D2: one row per place, with \(N + 1\) rows because the class token has a place too. For ViT-B/16 it has \(197\times768 = 151{,}296\) numbers, learned with the rest of the network (the 2017 transformer used the fixed sinusoids of D5 instead).

The table has structure. Over the 196 patch positions, two positions one patch apart have an average cosine of 0.73. For positions 3 apart it is 0.33, and for positions 10 apart −0.05 (pairs whose centres are 1, 3 or 10 patches apart, mostly in the same row or column). Same-row pairs 3 columns apart average 0.22, against −0.04 for pairs about as far apart that share neither row nor column. The ViT paper reports the same two features, closeness and a row and column pattern (Dosovitskiy and others, 2021). The fall with distance is not smooth: pairs 6 apart average 0.38, which is more than the 0.33 of pairs 3 apart. The paper notes a sinusoidal look in the position tables of larger grids, and this may be the same effect.

B. Move patches: the first k patches of a fixed random order are passed along in a circle, and the position vectors stay where they are

When all 196 patches are moved, ViT-B/16 still gives the same top call on 29% of the runs. ResNet-18 never does once 128 patches are moved. The measure is whether the call stays the same, which is not the same as being right: the unmoved call is wrong for some of these photos.

The plotted result is an average over 14 photos and 16 random orders (224 runs per point, from the 14 photos of the shark folder). At 16 patches moved the ViT keeps its call 76% of the time and ResNet-18 51%. At 64 moved: 66% and 16%. At 128 moved: 38% and 0%. A ViT, then, depends less on where a patch is, and more on what the patches contain: colours and textures. A study of DeiT models reached a similar conclusion (Naseer and others, 2021). The two networks were also trained with different recipes (torchvision's ViT-B/16 uses a modified DeiT recipe, ResNet-18 a simple one), so this run cannot separate architecture from training.

Common belief. Position embeddings are how a ViT learns the layout of a shark: fins above, tail behind.

Why it fails. With all patches moved the hammerhead photo still gets the call "hammerhead" (39%), and 29% of the runs on all photos keep their call. For labelling a whole photo, the content of the patches contains most of the answer.

Better account. Positions encode layout, and layout matters for tasks that ask where, such as finding the shark in the frame or counting animals. For a single label, texture and colour often decide. This is a measurement on 14 photos and one network, and it does not say that positions are useless.

Debug tip. If you feed a ViT a photo of a different size, the number of patches changes and the position table no longer has the right number of rows. Libraries resize the table by interpolating the patch rows in two dimensions. The class token's row must stay at index 0 and not be interpolated.

import numpy as np
rng = np.random.default_rng(4127)
n, d = 5, 4
X = rng.normal(size=(n, d))
Wq, Wk, Wv = (rng.normal(size=(d, d)) for _ in range(3))
def attend(X):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    s = Q @ K.T / np.sqrt(d)
    w = np.exp(s - s.max(1, keepdims=True)); w /= w.sum(1, keepdims=True)
    return w @ V
perm = np.array([3, 0, 4, 1, 2])
print(np.allclose(attend(X)[perm], attend(X[perm])))              # reorder the tokens: the outputs reorder
pos = rng.normal(size=(n, d))
print(np.allclose(attend(X + pos)[perm], attend(X[perm] + pos)))  # tokens move, positions stay: the outputs differ

Quick quiz

Why does attention without positions treat the patches as a set?

An output is a weighted sum over all tokens, with weights computed from the query and key vectors of the tokens. Reorder the tokens and the sums keep the same terms, so the outputs are the same vectors in a new order.

The page shows that a ViT keeps its call when patches move. Does that prove positions are useless?

No. It shows that for a one-word label of these 14 photos the patch contents contain most of the answer. Tasks that depend on layout were not tested.

The class token

Guess first. A transformer gives back one vector per token, so 196 vectors for 196 patches. A classifier needs one vector for the photo. Would you average the patch vectors, use the middle patch, or something else?

class token
one extra token placed before the patches; it starts as a learned vector with no pixels in it, and its final vector is the summary the classifier reads
head
here, the final linear layer that turns the class vector into scores for the 1,000 classes (not an attention head)
readout
the step that takes the answer out of the network

The class token is an empty slot that attention can fill. After 12 blocks its vector is a summary of the photo, and one linear layer turns it into scores.

In the first blocks the class token spreads its attention over nearly 100 patches. By the last blocks, ten patches have half of its patch attention. The maps are averages over the 12 heads of a block, and the brightest patch is drawn fully bright in all blocks.

Slide the block from 0 to 11. The class token goes through the same blocks, with the same weights, as the patch tokens. In a block it reads the patches (this is the map) and the patches may read it. In the hammerhead photo, 97 patches are needed to reach half of its patch attention at block 0, 42 at block 2 and 10 at block 11. In the same blocks it also puts 21% (block 0), 57% (block 2) and 37% (block 11) of its weight on itself, which is the first number in the boxes.

The class token starts with the same learned vector for all photos, so any difference in its final vector comes from what it read. After the 12th block, torchvision applies a layer norm and a linear layer with 768 × 1,000 + 1,000 = 769,000 numbers. For the hammerhead crop the top of the 1,000 scores is "hammerhead" at 88%. The same network calls the grey bamboo shark in its tank an electric ray (56%), and the spadenose crop an eel (31%). ImageNet has three shark classes (great white, tiger, hammerhead), so spadenose and bamboo sharks have no label of their own.

1,000×1scores=1,000×768Whead×768×1y, class vector after the last norm+1,000×1bias

\[ \mathbf{z}^{(0)}_0 = \mathbf{x}_{\text{class}},\qquad \mathbf{y} = \mathrm{LN}\big(\mathbf{z}^{(L)}_0\big),\qquad \text{scores} = W_{\text{head}}\,\mathbf{y} + \mathbf{b}_{\text{head}} \]

  • \(\mathbf{x}_{\text{class}}\) is the learned starting vector of the class token, with 768 numbers (the ViT paper writes it the same way). \(L\) is the number of blocks, 12, so \(\mathbf{z}^{(L)}_0\) is the class token after the last block.
  • \(\mathrm{LN}\) is layer norm (B6). The scores go through softmax as in A3 to give the probabilities.

Where it can mislead. A bright patch in the map shows where the class token read, which need not be where the evidence for the answer lies. B9 tests this on the same network and finds that flattening the last layer's attention changes the hammerhead score from 88% to 81%. The class token is also one design choice among others. The ViT paper compares it with averaging the patch vectors, and finds that both work similarly once the learning rate is tuned for the two designs.

Common belief. The class token is a special part of the model that looks at the picture.

Why it fails. It has no pixels and no weights of its own beyond a starting vector. It is one more token that the same attention and MLP weights act on.

Better account. It is a place to put an answer. Attention gives it a way to gather from the patches, and training decides what it gathers.

Debug tip. Averaging the patch vectors gives a usable summary, but a head trained on the class token will not work on the average without training. Mixing the two readouts between training and use is a quiet way to lose accuracy.

import numpy as np
rng = np.random.default_rng(4127)
d, n_classes = 768, 1000
y = rng.normal(size=d)                                  # the class vector after the last norm (made-up numbers)
W = rng.normal(0, 0.02, size=(n_classes, d))            # made-up head, one row per class
b = np.zeros(n_classes)
scores = W @ y + b
p = np.exp(scores - scores.max()); p /= p.sum()
print(scores.shape, W.size + b.size)
print(round(float(p.sum()), 3), int(p.argmax()), round(float(p.max()), 3))

The head turns 768 numbers into 1,000 scores. The numbers here are made up, so the winning class tells you little. With a trained head the winner is the call of the network.

Quick quiz

How many tokens does ViT-B/16 read for a 224 by 224 photo, and which one is read by the classifier?

The sequence has 197 tokens: the 196 patches and the class token. The classifier reads only the class token after the last block.

The class token has no pixels. How can its final vector depend on the photo?

In the blocks, attention lets it read the patch tokens, and the MLP and later blocks work on what it read. Its start is the same for all photos, and the difference comes from the patches.

Where a patch looks

Guess first. The first layer of a CNN reads a 3 by 3 window. In the first block of a ViT, a patch can attend to all 196 others. Do you expect the heads there to look mostly at neighbours, or all over the photo?

attention head
one of the parallel attention computations of a block, with its own weights (D4); 12 per block in ViT-B/16
attention distance
the average distance, in patches, between a patch and the patches it attends to, weighted by the attention
L2H5
layer 2, head 5, counting from 0, as in D4

A head has a habit. In this network a few heads look at neighbours, many look across the whole photo, and the habits change with depth.

Head L2H5 sends most of a patch's weight to its neighbours. Head L0H6 follows patches that look alike across the photo. The coral square is the query patch. The brightest patches get the most weight, and the shading is relative to the largest weight in the row.

Click a patch and switch heads. The six heads were picked by looking at the maps of all 144 heads for one query, to show the range. They are not an average, and other heads look different. The short descriptions of a head, such as "stays on the neighbours", say what its weights do for this query on these photos. They are descriptions of the maps and do not name a proven job of the head. The maps are stored at 16 levels, so shares are accurate to a point or two. The first row of boxes shows where the weight of this head goes: on the patch itself, on its eight neighbours, farther away, and on the class token. The second row gives the mean distance of the attention of this patch and of the whole head.

The measured distances for all heads are in the next section. In block 0 the heads attend on average 6.7 to 7.6 patches away. Even attention over the 196 patches would give 7.3. This does not mean that block 0 attends evenly. The map of L0H6 picks patches that look like the query, such as the body of the shark, and these lie far apart. Blocks 2 and 3 contain the most local heads (distance 1.5 for L2H5 and L3H7). The last blocks are wide again. Dosovitskiy and others (2021) found, for their ViT-L/16, that some heads attend widely in low layers and others locally, and that distance grows with depth. This ViT-B/16 differs in two ways. All 12 heads of block 0 are wide, and the local heads appear later, in blocks 2 to 4. So the mean distance falls from 7.0 in block 0 to 4.3 in block 4 and then rises to 7.3 in block 11. The two networks differ in size and in training. The paper's model saw a far larger set than ImageNet-1k, and torchvision's weights used a DeiT-style recipe. The pattern depends on the network and its training, and this page does not test which factor matters.

A worked case. The query patch at row 6, column 6 sends weight to the patch at row 6, column 9, which is 3 patches away. It also sends weight to row 9, column 10, which is \(\sqrt{3^2+4^2} = 5\) patches away. The attention distance of the patch is the average of such distances, weighted by the attention given. The late heads such as L7H6 put weight on a few patches of plain water. Darcet and others (2024) report high-norm tokens in background areas of other ViTs and show that they appear in the attention maps. This chapter did not test whether the same thing happens here.

\[ \bar d(q) = \frac{\sum_{k=1}^{N} a_{qk}\,\lVert \mathbf{p}_q - \mathbf{p}_k\rVert}{\sum_{k=1}^{N} a_{qk}} \]

  • \(a_{qk}\) is the attention weight of query patch \(q\) on patch \(k\) (D4). The sums skip the class token, so the denominator is the weight that falls on patches.
  • \(\mathbf{p}_q\) is the grid position (row, column) of patch \(q\), and \(\lVert\cdot\rVert\) the straight-line distance in patches. The distance of a head is the average of \(\bar d(q)\) over all queries and 14 photos.

Debug tip. A bright patch is not evidence. B9 shows that a head's map differs from a gradient map and that the answer remains under flattened attention. Treat these maps as a view of how information moves, and use occlusion (B9) to test what the answer needs.

import numpy as np
g = 14
r, c = np.divmod(np.arange(g * g), g)                   # grid row and column of the 196 patches
q = 6 * g + 6                                           # the query patch at row 6, column 6
dist = np.hypot(r - r[q], c - c[q])                     # distance in patches from the query to every patch
even = np.full(g * g, 1 / (g * g))                      # even attention: the same weight on all patches
near = np.exp(-dist ** 2 / 2); near /= near.sum()       # made-up weights that fall off with distance
print(dist[6 * g + 9], dist[9 * g + 10])
print(round(float((even * dist).sum()), 2), round(float((near * dist).sum()), 2))
D = np.hypot(r[:, None] - r[None, :], c[:, None] - c[None, :])   # distances between all pairs of patches
print(round(float(D.mean()), 2))                        # even attention, averaged over all queries

The first line repeats the worked case. Even attention gives 5.4 for this query, which is near the middle of the photo. Over all queries it gives 7.3 on average, since a query near an edge is far from most patches. The made-up weights that fall off with distance give 1.2.

Quick quiz

A head puts all its weight on the patch itself. What is its attention distance?

Zero patches. All terms of the sum have distance 0.

Why can a head with a large attention distance still be selective?

It can pick a few patches that look alike and lie far apart, such as the parts of one animal. Distance measures where the weight falls, not how concentrated it is.

ViT against CNN

Guess first. A CNN is built to read nearby pixels. A ViT can read any patch from the first block. Which of the two needs more training photos to learn to recognise sharks, and why?

inductive bias
what a model assumes before it sees any data, built into its design
locality
the assumption that nearby pixels belong together; a conv layer reads a small window
weight sharing
using the same weights at all positions (C2)
receptive field
the part of the photo that can change one number of a layer (C2)

A CNN assumes that nearby pixels matter first. A ViT assumes little, so it can learn more, and it needs more data to do so.

The left picture is drawn from the design of the two networks. The CNN window grows by one patch on all sides with a 3 by 3 layer, so after k layers it is 2k + 1 patches wide (C2). The ViT picture is not a measurement: it says that in block 1 a head can read all tokens. The charts are measured. They give the mean attention distance of a head. They also give the farthest that a stack of k layers reaches along the diagonal, which is \(k\sqrt{2}\) patches, and the share of attention that falls in a window. Five layers reach 7.1 patches, and block 0 heads attend 6.7 to 7.6 patches away on average.

Now the parameters. A ViT block has 12d² + 13d = 7,087,872 numbers for d = 768. Of these, 2,362,368 are in attention, 4,722,432 in the MLP and 3,072 in two norms (the same block as GPT-2 small in D5). Twelve blocks give 85,054,464, and with the patch matrix (590,592), the class token (768), the position table (151,296), the last norm (1,536) and the head (769,000) the total is 86,567,656. A 3 by 3 conv layer with 768 channels in and out has 5,309,184 numbers, which is more than the attention in a ViT block. Parameter counts do not tell the work. ViT-B/32 has 88.2 million numbers and ViT-B/16 has 86.6 million. The second needs 17.6 GFLOPs against 4.4 (torchvision's counts), since it runs the same blocks over 197 tokens and not 50.

All three ViTs in the list have at least 3.3 times as many numbers as ResNet-50, and the ViT-B/16 does 17.6 GFLOPs of work where ResNet-18 does 1.8. The torchvision accuracy on ImageNet-1k is 69.8% (ResNet-18), 76.1% (ResNet-50), 75.9% (ViT-B/32), 81.1% (ViT-B/16) and 79.7% (ViT-L/16). The weights were trained with different recipes, so the list compares packages and does not isolate the design.

What the data does. The ViT paper trained models on ImageNet alone, on ImageNet-21k and on JFT-300M. With ImageNet alone, ViT-Large did worse than ViT-Base. With the largest set, the large model won. Its authors conclude that large-scale training outweighs the lack of an image bias (Dosovitskiy and others, 2021). Where a CNN's locality helps, a small training set is enough. Where the data is large, the ViT can learn what a CNN assumes and more. For SharkCam, with a few thousand photos, a pretrained network of either kind is the starting point, and the fine-tuning of B7 does the rest.

Common belief. Transformers replaced CNNs because they are better.

Why it fails. With ImageNet alone, the larger ViT did worse than the smaller one. On the torchvision list, ViT-B/16 needs far more numbers and work than ResNet-18 to gain 11 points of accuracy, and it was trained with a different recipe. On a small robot (F2) work counts.

Better account. The two designs make different assumptions. Which works better depends on the amount of data, the compute available and the task. Many models combine them, with convolutions for the first layers and attention above.

Quick quiz

What does a CNN assume that a ViT does not?

Locality (nearby pixels matter first) and the same filters at all positions, built into all layers. A ViT shares weights across tokens, but its attention can read any token from the first block.

ViT-B/32 and ViT-B/16 have almost the same number of weights. Why does ViT-B/16 cost about four times more work?

The weights are the same blocks. B/16 runs them over 197 tokens and B/32 over 50, and the work grows with the number of tokens (and with its square in attention).

Discrete image tokens

Guess first. A text token is a whole number: an ID in a vocabulary (D1). A patch token so far is a list of 768 numbers with decimals. If you wanted to give a language model the whole photo as a sentence, what would you need?

vector quantisation
replacing a vector by the nearest entry of a short list of vectors
code book
that list: K vectors with IDs from 0 to K − 1
image token
the ID of the code that replaces a patch

Replace the patches by the IDs of their nearest code-book entries, and a photo becomes a short sentence of integers that a language model can read or write.

With 256 codes, the 784 patches become 784 integers and the picture is recognisable but blocky. With 4 codes it is a few flat tones. The code books here come from plain k-means on 8 by 8 pixel patches of 11 other photos.

Click a patch. The page finds the code with the smallest squared distance to the patch's 192 numbers, and the rebuilt picture uses the code's pixels. This is vector quantisation. The simplest way to make the code book is k-means: the code book is the set of K cluster centres. Check the sizes. A photo of 224 × 224 × 3 × 8 = 1,204,224 bits becomes 784 tokens of 8 bits (K = 256), which is 6,272 bits, 192 times smaller. The fit is poor: details are gone, and many patches of water or sand share one code. A code book is a dictionary, and the token is the dictionary entry. This is also how subwords work in D1, with a difference: the entry is chosen by distance, not by merges.

\[ k^*(i) = \arg\min_{k\in\{0,\dots,K-1\}} \lVert \mathbf{x}_i - \mathbf{c}_k\rVert^2,\qquad \text{bits per token} = \log_2 K \]

  • \(\mathbf{x}_i\) is patch \(i\) as a list of numbers (192 for an 8 by 8 patch with three colours). \(\mathbf{c}_k\) is code \(k\) of the code book, and \(k^*(i)\) is the ID that becomes the image token.
  • \(\arg\min\) means "the \(k\) that makes the squared distance smallest". \(K\) is the number of codes, and \(\log_2 K\) is the number of bits needed to write one ID (8 bits for 256 codes).

The toy here works on raw pixels. Systems that make image tokens for language models learn the codes inside a network. In the VQ-VAE (van den Oord and others, 2017) an encoder network maps the photo to a grid of vectors. These vectors are replaced by their nearest entries of a learned code book, and a decoder rebuilds the picture from the entries. The nearest-entry step has no slope, so training copies the decoder's slope back to the encoder as if the step were not there. DALL-E (Ramesh and others, 2021) uses a related discrete autoencoder to compress a 256 by 256 photo into a 32 by 32 grid of tokens from a vocabulary of 8,192. This cuts the length that the transformer must model by a factor of 192. Esser and others (2021) learn the codes with a CNN and model the tokens with an autoregressive transformer, which is the next-token prediction of D3. A practical limit: some codes are used rarely or never (the dark tiles above), which wastes the book.

Common belief. An image token is a piece of the picture.

Why it fails. In this toy it is, because the codes are raw pixels. In a learned system the code is an entry that the decoder turns into pixels together with its neighbours. It says "something like this goes here". The codes cannot be read back into patches without the decoder.

Better account. An image token is an ID in a vocabulary of visual words, chosen by closeness. Its meaning comes from the dictionary and the decoder, as the meaning of a text token comes from its embedding.

Debug tip. When a quantiser gives blurry pictures, count the codes used. If only a handful of the 256 are used, the code book has collapsed. The fix is in training (restart unused codes, or use a smaller code book) and the decoder is not at fault. The readout above shows this count.

import numpy as np
# vector quantisation of 2 by 2 grey patches (made-up numbers)
patches = np.array([[10, 12, 11, 9], [200, 210, 205, 198], [120, 20, 118, 25], [15, 14, 13, 12]], float)
book = np.array([[10, 10, 10, 10], [200, 200, 200, 200], [120, 20, 120, 20]], float)
d2 = ((patches[:, None, :] - book[None, :, :]) ** 2).sum(2)
codes = d2.argmin(1)
print(codes)
print(np.round(np.sqrt(d2.min(1) / 4), 1))     # typical gap per number
print(np.log2(len(book)))                      # bits per token

Quick quiz

A code book has 1,024 codes and a photo becomes 256 tokens. How many bits is the photo?

log2 1,024 = 10 bits per token, so 256 × 10 = 2,560 bits.

What is lost when a patch is replaced by its nearest code?

The detail that distinguishes the patch from its code, such as fine texture and small differences in colour. A larger code book loses less and costs more bits per token.
