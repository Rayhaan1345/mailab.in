Values, names and decisions

Guess first. After the two lines length = 62 and length = length + 5, what does length contain? In algebra the second line would be impossible.

variable
a name attached to a value
type
the kind of value: int (whole number), float (decimal), str (text) or bool (True or False)

an expression whose value is True or False

A variable is a name tag attached to a value, and = moves the tag. It does not state an equation.

    Where it breaks. A box contains one copy. Two names can point to the same list, and then a change through one name shows through the other (next section). The name-tag picture describes that correctly: tags are cheap, and one value can wear several.

    Quick quiz

    What are the types of 7, 7.0 and "7"?

    An int, a float and a string. They print alike but behave differently: "7" * 2 is "77", while 7 * 2 is 14.

    With cut-offs 45 and 70, which branch runs for a length of 45?

    The second one. The test 45 < 45 is False, so Python moves on to elif length < 70, which is True. The answer is "sub-adult".

    Sub-adult. Both tests are True and the second assignment overwrites the first. With elif Python would stop after the first True test.

    Functions

    Guess first. A function computes a variable grams inside its body and returns a result. After the call, can the rest of the program print grams?

    function
    named code that takes values in and sends a value out
    parameter
    a name in the definition that receives an input; the values you pass are the arguments
    return value
    what the call evaluates to
    scope
    where a name can be seen; names made inside a function are local to it
    default argument
    a value used when the caller gives none

    A function is a small program with its own private names. Values go in through parameters and one value comes out through return.

    The names length_cm, a, b and grams exist only during the call. After it returns, the program sees the value and no other names.

    The length-weight law W = a L^b turns a length into a weight, with two numbers a and b that depend on the species. The defaults here are the grey bamboo shark's values, so weight_kg(44.0) gives the weight of Tag 4127, the juvenile bamboo shark from the Juhu rock pool. A caller can pass the numbers for another species by position or by name. The ideas behind functions as maps from inputs to outputs are in 0.3.

    return grams / 1000

    A function can return several values as a tuple, which the caller unpacks. The one-line form a if test else b picks a when the test is True and b otherwise. An assert line is a test: it has no effect when its statement is True and stops the program with an AssertionError when it is False.

    Common belief. A function works on its own copy of whatever you pass in.

    Why it fails. Python passes the name tag, not a copy. If a function appends to a list it received, the caller's list changes too. A number or a string cannot be changed in place, so reassigning it inside the function leaves the caller's value alone.

    Better account. Treat a list argument as shared. If the function should not change the caller's list, work on lengths.copy() inside it.

    Debug tip. A function with no return gives back None. This shows up as a long chain of "NoneType" errors far from the cause. Print the value that a call returns before you use it.

    def grow(length_cm):
    length_cm + 5          # computed, then thrown away

print(grow(40))
    None

    Debug tip. A default value is made once, when the function is defined. A list used as a default is therefore shared by all calls. Use None as the default and make the list inside the function.

    return seen

    In practice: give a function one job and a name that says it. Short functions are easy to test with an assert. Put numbers that may change, such as a and b, in parameters with defaults.

    Classes: a Shark object

    Guess first. You build two Shark objects from the same class, then grow one of them by 5 cm. Does the other one grow too?

    class
    a blueprint that says what data an object has and what it can do
    object
    one thing built from a class; also called an instance
    attribute
    a value stored on an object, such as shark.length_cm
    method
    a function attached to an object, called as shark.grow(5)
    self
    the name a method uses for the object it was called on

    A class bundles data with the functions that use it, and objects made from it keep separate copies of the data.

    Growing one shark leaves the others as they were, because the length belongs to the object and not to the class. Make a second shark, then grow only one.

    The line def __init__(self, tag, species, length_cm) runs when you write Shark(4127, ...). It stores the arguments on the new object. Tag 4127 is the juvenile grey bamboo shark found in a Juhu rock pool, and Tag 3305 is an adult spadenose shark from a landing. Both are records of the made-up catch table.

    # (a, b) of W = a * L**b, in grams
LAW = {"spadenose": (0.0044, 2.923),
       "milk": (0.0033, 3.051),
       "bamboo": (0.00398, 2.95)}

class Shark:
    def __init__(self, tag, species, length_cm):
        self.tag = tag
        self.species = species
        self.length_cm = length_cm

    def weight_kg(self):
        a, b = LAW[self.species]
        return a * self.length_cm ** b / 1000

    def grow(self, cm):
        self.length_cm = self.length_cm + cm

    def __repr__(self):
        return f"Shark({self.tag}, {self.species!r}, {self.length_cm} cm)"

a = Shark(4127, "bamboo", 44.0)      # the Juhu bamboo shark
b = Shark(3305, "spadenose", 41.0)   # the Sassoon spadenose
print(a, round(a.weight_kg(), 3))
print(b, round(b.weight_kg(), 3))
a.grow(5)
print(a, round(a.weight_kg(), 3))
print(b)

    The dictionary LAW lives outside the class and stores the two numbers of a species. The method __repr__ tells Python how to show the object as text. Names with double underscores are hooks that Python calls for you. The first two weights, 0.281 and 0.228 kg, are the weights of the two records in the table.

    Follow Tag 4127 through grow(5). The method receives the object as self, so self.length_cm is 44.0. It stores 49.0 on that object only. The next weight_kg() call returns 0.385 kg. The shark is 11% longer (49.0 / 44.0) and about 37% heavier (0.385 / 0.281), because weight follows length to a power near 3 (0.3).

    Objects are shared the way lists are. After twin = a there is one shark with two names, so growing twin grows a. The block uses @dataclass, which writes __init__ and __repr__ for you, and sorts objects by a method. The sort key lambda s: s.weight_kg() is a one-line function that returns the weight of a shark.

    from dataclasses import dataclass

LAW = {"spadenose": (0.0044, 2.923), "bamboo": (0.00398, 2.95)}

@dataclass
class Shark:
    tag: int
    species: str
    length_cm: float

    def weight_kg(self):
        a, b = LAW[self.species]
        return a * self.length_cm ** b / 1000

sharks = [Shark(4127, "bamboo", 44.0), Shark(3305, "spadenose", 41.0)]
print(sharks[0])
for s in sorted(sharks, key=lambda s: s.weight_kg()):
    print(s.tag, round(s.weight_kg(), 3))

twin = sharks[0]               # a second name, not a second shark
twin.length_cm = 49.0
print(sharks[0].length_cm)

    In practice: write a class when data and the functions that use it belong together. A table of thousands of records is better as a DataFrame than as a list of objects. Keep classes small.

    Analogy. A class is a blueprint and an object is a house built from it. Changing one house leaves the others as they were.

    Where it breaks. A paper blueprint only describes. A Python class also exists in the running program, and a value stored on the class instead of on self is shared by all objects made from it. This chapter stores values on self only, which is why the objects stay separate.

    Debug tip. A method always needs self as its first parameter. Python passes the object in as the first argument, so a method that lacks self reports one more argument than you typed.

    Quick quiz

    In self.length_cm = length_cm, which side is the attribute?

    The left side. self.length_cm is stored on the object. The right side is the parameter that was passed in.

    Broadcasting and matrix products
    
  
    Guess first. A table has 4 sharks and 3 measurements, so its dimensions are (4, 3). You want to subtract the mean of a column from that column. Will an array of 3 means work in one line? What about an array of 4 values?
    
  
    
    
    broadcasting
    the rule that stretches a size-1 (or missing) dimension to match the other array
    
    
    compatible
    two sizes are compatible when they are equal or when one of them is 1
    
    
    matrix product
    written A @ B; its meaning is in 0.5, and here you learn only which sizes it accepts
    
  
    
  
    NumPy lines up the dimensions of two arrays from the last one backwards. A pair works when the sizes are equal or one is 1. Otherwise the operation fails.
    
  
    
    
    
    
    
    
    Try these
    
    
    
    
    
    
    
    
    
  
    
  
    Faded cells show the stretched copies, which NumPy reuses without storing them again. A result exists only when all dimensions pass the rule. For @ the rule is different: the last dimension of A must equal the second-to-last dimension of B, and both vanish from the result.
    
  
    Read the rule table under the grids from the bottom up, starting at the last dimension of both arrays. A missing dimension counts as 1. Pick (4, 3) and (3,), then (4, 3) and (4,), and compare the two tables. The second pair fails because 3 and 4 differ and neither is 1.
    
  
    The fix for the failing pair is to give the 4 values a second dimension of size 1, so they have dimensions (4, 1). The size-1 dimension is then stretched across the 3 columns. Choose (4, 1) in the explorer and see the faded copies.
    
  
    (4, 3)table+(3,)column means→(4, 3)result: the means are stretched down the rows
    
  
    \[ \text{result size}_i = \max(a_i, b_i) \quad\text{if}\quad a_i = b_i \ \text{or}\ a_i = 1 \ \text{or}\ b_i = 1 \]
    
  
      
    
    • \(a_i\), \(b_i\) are the sizes of the two arrays along dimension \(i\), counted from the right. A missing dimension counts as 1.
      • 
    
    • \(\max(a_i, b_i)\) is the size of the result there: the larger of the two, since the other is either equal or 1.
      •

    • \(m\) rows in the first array, \(n\) columns in the second.
      • 
    
    • \(k\) is the shared size. It must match, and it disappears from the result.

    Common belief. Some seeds are good seeds. Seed 42 is the right one, and a result that needs it is the true result.
    
    
    Why it fails. A seed only picks one of many equally valid random sequences. A different seed gives a different split of the data and a different score.

    Quick quiz
    
    
    You rerun a script with no seed and the score moves from 0.81 to 0.78. Is the model worse?

    PyTorch in one page
    
  
    Guess first. You have a loss that depends on a weight w, and you want the slope of the loss with respect to w. Do you work it out by hand and type it in, or can the library find it?
    
  
    
    
    tensor
    PyTorch's array; it can also run on a GPU and record how it was made
    
    
    requires_grad
    a flag asking PyTorch to track all operations on a tensor
    
    
    autograd
    the part of PyTorch that computes gradients automatically
    
    
    .backward()
    computes the gradient of one number (the loss) with respect to all tracked tensors
    
    
    .grad
    the attribute where that gradient is stored
    
  
    
  
    A tensor with requires_grad=True remembers the operations that used it. Calling loss.backward() walks back through them and fills in w.grad.
    
  
    
    
    
    
    
    
    
    
    
  
    
  
    The sign of w.grad says which way to move w: positive means lower it, negative means raise it. Press the step button repeatedly and the loss shrinks while the line approaches the points.
    
  
    The model is a line, \(\hat y = w x + b\), through the three recurring sharks: Tag 3305, Tag 4127 and Tag 5519. The loss is the mean of the squared vertical gaps. PyTorch finds \(\partial L/\partial w\) and \(\partial L/\partial b\) by applying the chain rule to the recorded operations. The chapter on slopes (0.6) shows why those rules apply, and B4 builds the same machine by hand. The numbers in the figure are computed with the formulas below and match PyTorch to all printed digits.
    
  
    \[ \begin{aligned} L &= \frac{1}{m}\sum_{i=1}^{m} (w x_i + b - y_i)^2 \\ \frac{\partial L}{\partial w} &= \frac{2}{m}\sum_{i=1}^{m} (\hat y_i - y_i)\, x_i \\ \frac{\partial L}{\partial b} &= \frac{2}{m}\sum_{i=1}^{m} (\hat y_i - y_i) \end{aligned} \]
    
  
      
    
    • \(x_i\) is the length of shark \(i\) in metres, \(y_i\) its weight in kg, and \(\hat y_i = w x_i + b\) the line's prediction. The lengths and weights are the three recurring records of the made-up catch table. A straight line fits weight against length poorly, because weight grows faster than length; A2 shows the fix.
      • 
    
    • \(m\) is the number of sharks, here 3. \(w\) and \(b\) are the slope and the intercept.
      • 
  
    
  
    Here is the same computation in PyTorch. There is no Run button because the in-browser Python has no PyTorch; the output below came from PyTorch 2.6.0.
    
  
    import torch

x = torch.tensor([0.41, 0.44, 0.82])      # lengths in metres: Tags 3305, 4127, 5519
y = torch.tensor([0.228, 0.281, 2.610])   # weights in kg (made-up records)
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

pred = w * x + b
loss = ((pred - y) ** 2).mean()
print(round(loss.item(), 4))

loss.backward()
print(round(w.grad.item(), 4), round(b.grad.item(), 4))
    
  
    1.0875
-0.8821 -0.966
    
  
    Check the numbers by hand. At \(w = 1\) and \(b = 0\) the predictions equal the lengths. The errors \(\hat y - y\) are 0.182, 0.159 and \(-1.790\), with squares 0.0331, 0.0253 and 3.2041. Their mean, 3.2625 / 3, is the printed loss, 1.0875. For \(\partial L/\partial w\), multiply the errors by the lengths, add, and multiply by 2/3: \(\tfrac{2}{3}(0.0746 + 0.0700 - 1.4678) = -0.8821\). For \(\partial L/\partial b\) the lengths drop out: \(\tfrac{2}{3}(0.182 + 0.159 - 1.790) = -0.966\). Both are negative, so raising \(w\) or \(b\) lowers the loss. The heaviest shark causes the large third error.
    
  
    L = 1.0875loss→−0.8821∂L/∂w&−0.966∂L/∂b
    
  
    Autograd multiplies local slopes, which is the chain rule (0.6). Take \(u = 3w + 1\) and \(L = u^2\) at \(w = 2\). Then \(u = 7\) and \(L = 49\). The slope of \(u\) with respect to \(w\) is 3, and the slope of \(L\) with respect to \(u\) is \(2u = 14\). The product, 42, is w.grad.
    
  
    import torch

w = torch.tensor(2.0, requires_grad=True)
u = 3 * w + 1          # 7
L = u ** 2             # 49
L.backward()
print(u.item(), L.item(), w.grad.item())
    
  
    7.0 49.0 42.0
    
  
    One step of gradient descent moves the numbers a small distance against its gradient. The step is made with torch.no_grad() so that the update itself is not recorded. Gradient descent is the topic of A2.
    
  
    import torch

x = torch.tensor([0.41, 0.44, 0.82])
y = torch.tensor([0.228, 0.281, 2.610])
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
lr = 0.5

for step in range(50):
    loss = ((w * x + b - y) ** 2).mean()
    loss.backward()
    with torch.no_grad():
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_()
    b.grad.zero_()

print(round(w.item(), 3), round(b.item(), 3), round(loss.item(), 4))
    
  
    4.711 -1.564 0.0589
    
  
    Working code hands the loop to an optimiser: opt.zero_grad() clears the gradients, loss.backward() fills them and opt.step() applies the update. The result is the same. A training loop always has these parts: forward pass, loss, clear, backward, step.
    
  
    import torch

x = torch.tensor([0.41, 0.44, 0.82])
y = torch.tensor([0.228, 0.281, 2.610])
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
opt = torch.optim.SGD([w, b], lr=0.5)

for step in range(50):
    opt.zero_grad()                       # clear the old gradients
    loss = ((w * x + b - y) ** 2).mean()
    loss.backward()
    opt.step()                            # w -= lr * w.grad, b -= lr * b.grad

print(round(w.item(), 3), round(b.item(), 3), round(loss.item(), 4))
    
  
    4.711 -1.564 0.0589
    
  
    
    
    Debug tip. Calling backward() twice adds to .grad instead of replacing it. Training loops clear the gradients once per step (zero_grad() on an optimiser, or .grad.zero_() as above). Forgetting this makes updates larger than they should be, and the loss behaves oddly.

    PyTorch and NumPy convert into one another cheaply. The two objects then share memory, so a change to one shows in the other. A second trap is the default number type: torch.tensor([1.0]) is 32-bit (float32) while a NumPy array is 64-bit (float64). Mixing them in some operations, such as the layers of a network, raises a dtype error until you convert with .float() or .double().

    Common belief. Autograd differentiates your formula symbolically, like a computer algebra system.
    
    
    Why it fails. It differentiates the numbers that actually flowed through your code, one operation at a time, and it multiplies the local slopes together. It never builds a formula.
    
    
    Better account. Autograd is a recording of one run plus the chain rule. That is why if statements and loops work, and why a step like rounding, which has a slope of 0 at nearly all points, gives useless gradients.

    Quick quiz
    
    
    Which tensors get a .grad after loss.backward()?
    The ones created with requires_grad=True that took part in computing the loss, here w and b. The data tensors x and y do not.
    
    
    What happens to w.grad if you call backward() in a loop and never zero it?
    It keeps adding up. The next step then uses a sum of old and new gradients, which is usually wrong.
    
    
    With \(u = 3w + 1\) and \(L = u^2\), what is w.grad at \(w = 2\)?
    It is 42. The slope of \(u\) is 3 and the slope of \(L\) at \(u = 7\) is 14, and autograd multiplies them.
