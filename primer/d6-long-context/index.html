Long context

What a longer text costs, and four ways to pay less

In D4 a token compared itself with all the tokens before it, so the number of comparisons grows with the square of the length. This chapter counts that cost in time and in memory. It starts with one report of 33 tokens and ends with the SharkCam dive log, which is about 78,000 tokens when it is written out as sentences. Then it follows four ways to pay less. The first computes fewer pairs (Sparse Transformer, Longformer, BigBird). The second cuts a trained model's attention to a window. The third keeps a memory of fixed size (linear attention and state-space models). The fourth lets the model train its memory while it reads. That last route is test-time training, the family of In-Place TTT, which my MBZUAI project works on.

The dive log is the made-up log of the running example. Token counts come from the GPT-2 and Qwen2.5 tokenizers. The window experiment uses GPT-2 small on a 1,024-token logbook built from the invented reports and the made-up log. The memory figures use made-up keys and values.

You will need: attention and the causal mask (D4), the KV cache (D5), Big-O (0.2) and the outer product (0.5).

What a longer text costs

Guess first. A text becomes twice as long. By what factor does the number of attention comparisons grow? By what factor does the rest of the work in a layer grow? For a very long text, which of the two is the bigger bill?

pair
one query token compared with one key token (D4)
multiply-add
one multiplication and one addition, the unit of work counted here
attention matrix
the table of attention weights, one row per query token (D4)
quadratic
growing like \(n^2\): doubling the length makes it four times as large (0.2)

The comparisons grow with the square of the length and the other work in a layer grows in a straight line, so past some length attention is the larger part.

With the sizes of GPT-2 small, attention is 10% of a layer's work at 1,024 tokens, 78% at 32,768 and 93% at 131,072. The lines cross at about 9,200 tokens here and at about 24,600 tokens for the sizes of Qwen3-4B.

Move the length slider, or press the SharkCam buttons. A report is about 33 tokens in GPT-2's tokenizer. A logbook of 500 reports comes to about 16,400 tokens. The made-up dive log has 2,400 frames, one per second for 40 minutes. Written out as one sentence per frame ("At 313 s the camera was at 12.39 m, light 0.02473, ...") it is 211,412 characters. That is 78,163 GPT-2 tokens, or 109,699 tokens in the Qwen2.5 tokenizer, which cuts numbers into single digits (D1). As photos it is larger still. If a frame is a 224 by 224 photo cut into 16 by 16 patches (E1), a frame is 196 tokens and the dive is 470,400.

The two lines count different things. The coral line counts attention pairs. For one pair the model computes a score, a dot product of two vectors of \(d_{\text{head}}\) numbers, and later a weighted sum that costs the same again. Over all heads, \(H\, d_{\text{head}} = d_a\), so one pair costs \(2 d_a\) multiply-adds. With the causal mask the pairs are \(1 + 2 + \dots + n = n(n+1)/2\). The navy line counts the rest of the layer: the matrices that make queries, keys, values and outputs, and the MLP. They work on one token at a time, so their cost is the number of tokens times the number of weights, \(P_{\text{block}}\).

\[ T_{\text{attention}} = 2\,d_a\cdot\frac{n(n+1)}{2} = n(n+1)\,d_a, \qquad T_{\text{rest}} = n\,P_{\text{block}}, \qquad n^{*} = \frac{P_{\text{block}}}{d_a} - 1 \]

  • \(n\) is the number of tokens. \(d_a\) is the width of the attention, the number of heads times the head size: 768 in GPT-2 small and 4,096 in Qwen3-4B (32 heads of 128).
  • \(P_{\text{block}}\) is the number of weights in one block that act on one token at a time (attention projections and MLP). It is 7,087,872 in GPT-2 small (D5) and 100,925,440 in Qwen3-4B, computed from its configuration file.
  • \(n^{*}\) is the length at which the two costs are equal. Solve \(n(n+1)d_a = n\,P_{\text{block}}\) for \(n\).

Worked example 1. GPT-2 small at \(n = 1{,}024\): attention costs \(1{,}024 \times 1{,}025 \times 768 = 806{,}092{,}800\) multiply-adds, and the rest costs \(1{,}024 \times 7{,}087{,}872 = 7{,}257{,}980{,}928\). Attention is \(0.81 / (0.81 + 7.26) = 10\%\) of the layer. Worked example 2. At \(n = 32{,}768\) attention costs 824.7 billion and the rest 232.3 billion, so attention is 78%. The crossing point is \(n^{*} = 7{,}087{,}872 / 768 - 1 = 9{,}228\). Vaswani and others (2017) list the same cost, \(O(n^2 d)\) per layer, in their Table 1, next to \(O(n d^2)\) for a recurrent layer. Attention is the cheaper of the two when \(n < d\).

Memory has its own count. The attention matrix has \(n^2\) numbers per head and layer. At \(n = 32{,}768\) that is 1.07 billion numbers, or 2.1 GB in 16-bit numbers, for one head in one layer, and Qwen3-4B has 32 heads per layer. Programs avoid storing it. FlashAttention (Dao and others, 2022) computes the same result in tiles that stay in fast memory, so the full table is never written out. This lowers the memory and the traffic. The number of pairs stays the same, and so does the \(n^2\) in the time.

Common belief. Attention is the slow part of a transformer, so a longer text always means a mostly attention bill.

Why it fails. At 1,024 tokens attention is a tenth of a layer in GPT-2 small, and the weights that act on one token at a time do the rest. The square only wins once \(n\) passes \(P_{\text{block}} / d_a\). A wider model has a larger crossing point, because \(P_{\text{block}}\) grows like \(d^2\) and \(d_a\) like \(d\).

Better account. Both costs matter. For short texts the weights dominate, for long texts the pairs dominate, and the crossing point depends on the model. While a model writes, a new token is compared with the \(n\) tokens in the cache, which costs \(n\,d_a\) and reads the whole cache from memory.

Debug tip. Count tokens, not words or characters. The dive log as sentences is 211,412 characters but 78,163 tokens. A Hindi report costs about five times as many tokens as its English meaning in GPT-2 (D1). The pairs grow with the square of the token count, so a language that costs five times the tokens costs about 25 times the pairs. The 117-token Hindi report has 6,903 kept scores under the causal mask of D4, against 276 for its 23-token English meaning.

def layer_cost(n, d_attn, w_block):
    attn = n * (n + 1) * d_attn          # score and weighted sum, allowed pairs only
    rest = n * w_block                   # projections and MLP: one pass per token
    return attn, rest

Quick quiz

A text grows from 8,192 to 16,384 tokens. By what factor do the attention pairs grow, and by what factor does the rest of the layer's work grow?

The pairs grow by \(16{,}384 \times 16{,}385 / (8{,}192 \times 8{,}193) = 4.0\), and the rest by 2.

Why does a wider model reach the crossing point at a longer text?

\(n^{*} = P_{\text{block}} / d_a - 1\). The numerator grows like \(d^2\) and the denominator like \(d\), so \(n^{*}\) grows with the width. GPT-2 small crosses at 9,228 tokens and Qwen3-4B at 24,639.

The key-value cache at actual sizes

Guess first. Qwen3-4B reads a report of 32,768 tokens. Its weights take about 8 GB in 16-bit numbers. Does the KV cache of the report take about 5 MB, about 5 GB or about 50 GB?

key-value head
a head with its own stored keys and values; in a model with grouped-query attention it serves a group of query heads
grouped-query attention
several query heads share one key-value head, so the cache is smaller (Ainslie and others, 2023)
head size \(d_{\text{head}}\)
the number of numbers in a key or a value of one head (D4)

The cache grows in a straight line with the length, and for a long text it is larger than the weights of the model.

Qwen3-4B needs 4.8 GB of cache for 32,768 tokens and 19.3 GB for 131,072. At about 54,500 tokens its cache is as large as its weights. The dotted line is the memory you chose with the second slider. Sizes come from the configuration files of the models and use 1 GB = 1,000,000,000 bytes.

Choose a model and move the length. The formula in D5 was \(2 \times N_{\text{layer}} \times n \times d \times b\), and it assumed that all heads keep their own keys and values, as GPT-2 does. Newer models share. Qwen3-4B has 32 query heads but 8 key-value heads (its configuration file says num_key_value_heads: 8), so a group of 4 query heads reads one set of keys and values. Qwen2.5-0.5B has 14 query heads and 2 key-value heads. The cache therefore stores \(n_{kv}\) heads of size \(d_{\text{head}}\) per layer, and the pale bar in the figure shows what it would be without sharing.

\[ \text{cache size in bytes} = 2\times N_{\text{layer}}\times n_{kv}\times d_{\text{head}}\times n\times b \]

  • 2 is for keys and values. \(N_{\text{layer}}\) counts the layers that keep a key and a value for all tokens. \(n_{kv}\) is the number of key-value heads and \(d_{\text{head}}\) the numbers per head. \(n\) is the number of tokens and \(b\) the bytes per number (2 for 16-bit).
  • Without sharing, \(n_{kv} d_{\text{head}} = d\), the formula of D5.

Worked example 1. Qwen3-4B has 36 layers, 8 key-value heads and a head size of 128. For one token: \(2 \times 36 \times 8 \times 128 \times 2 = 147{,}456\) bytes. For 32,768 tokens: \(147{,}456 \times 32{,}768 = 4{,}831{,}838{,}208\) bytes, or 4.8 GB. Without sharing it would have 32 key-value heads and the cache would be four times as large, 19.3 GB. Worked example 2. The SharkCam dive log written as sentences is 109,699 tokens in the Qwen2.5 tokenizer. Both configuration files give a vocabulary of 151,936, but this primer did not compare the two tokenizers, so take the count as an estimate for Qwen3. Its cache in Qwen3-4B's sizes would be \(147{,}456 \times 109{,}699 = 16.2\) GB, twice the weights. The configuration file gives Qwen3-4B a position limit of 40,960 tokens, so a text this long also needs position scaling (D5).

Select the last model, Qwen3.6-27B. Its configuration file lists 64 layers, of which 16 are labelled full_attention and 48 linear_attention. Only the 16 keep keys and values for all tokens. The other 48 keep a state of fixed size, which the next sections explain. The figure adds an estimate of that state: a 128 by 128 matrix for 48 value heads in 48 layers, read from the configuration (the model's code was not read). It is small next to the growing cache.

A bigger cache also makes the model slower, because a decoding step reads the whole cache from memory to attend over it. Practitioners shrink the cache in four ways. They share keys and values (grouped-query attention). They store them in 8-bit numbers, which halves the cache, and the effect on answers has to be measured per model. They drop old tokens (the next sections). They use fewer full layers (the hybrid model above).

Common belief. A model with a window of 128,000 tokens reads 128,000 tokens as well as it reads 1,000.

Why it fails. The window says what fits, and the cache says what it costs. Neither says how well the model uses the text. Liu and others (2023) placed the relevant passage at different positions in a long input. Models answered best when it was at the beginning or the end, and worse when it was in the middle. The same was found for models built for long contexts.

Better account. Window size, cost and use are three separate numbers. The first two can be computed. The third has to be tested on your own task.

Debug tip. To estimate a cache, read num_key_value_heads in the configuration, not num_attention_heads. For Qwen3-4B the wrong one overestimates the cache four times.

def kv_bytes(layers, kv_heads, head_dim, n, bytes_per_number=2):

Quick quiz

Qwen2.5-0.5B has 24 layers, 2 key-value heads of size 64. How many bytes of cache does one token need in 16-bit numbers?

\(2 \times 24 \times 2 \times 64 \times 2 = 12{,}288\) bytes. For 32,768 tokens that is 403 MB.

Why does the cache of the hybrid model grow more slowly than that of a 64-layer model with full attention in all layers?

Only 16 of its 64 layers keep keys and values for all tokens. The other 48 keep a state whose size does not depend on \(n\).

Looking at fewer pairs

Guess first. For 4,096 tokens, causal attention computes 8,390,656 pairs. If a token may look only at the last 64 tokens, about what share of the pairs remains? Which few extra pairs would you add so that a token can still reach far?

sparse attention
computing only some of the \(n^2\) pairs
sliding window
a token looks only at the \(w\) tokens nearest to it (Longformer)
stride \(l\)
a token also looks at tokens \(l\), \(2l\), \(3l\), ... places back (Sparse Transformer)
global token
a token that looks at all tokens and that all tokens look at (Longformer, BigBird)
random attention
a few keys chosen at random per query (BigBird)

A mask decides which pairs are computed. If it keeps the near pairs, a few global ones and a few far ones, the number of pairs grows in proportion to \(n\), or to \(n\sqrt{n}\), instead of \(n^2\).

With a window, the work per token stops growing with the length. Doubling the length multiplies the window line in the chart by 2 and the full line by 4. At the start (n = 64, w = 8) the window computes 484 of 2,080 pairs. The chart is log-log, so a pattern whose line is parallel to the full line still has a square in it.

A row of the grid is one query token and a column is one key token. A filled cell is a pair that is computed. Start with the sliding window and raise \(n\). The filled band stays as wide as \(w\), so the line in the chart grows in step with \(n\) and leaves the full line behind. Then try the others.

  • Sliding window. Longformer (Beltagy and others, 2020) gives a token a fixed window of \(w\) tokens, \(w/2\) on both sides, and the cost is \(O(n \times w)\). In the left-to-right version the window is the last \(w\) tokens, the token itself included.
  • Strided. The Sparse Transformer (Child and others, 2019) uses two kinds of head: one looks at the previous \(l\) places and one at the places \(l\), \(2l\), \(3l\), ... back. The figure shows both together. With \(l\) near \(\sqrt{n}\) the total is \(O(n\sqrt{n})\), and any two tokens are joined in two steps. Switch the stride to the square root of \(n\) and watch the slope of the line in the chart. The authors found that a strided pattern suits data with a natural stride, such as images, and that for text a fixed pattern works better.
  • Global + window. A few tokens, such as the classification token of an encoder, look at all tokens and are seen by all. Longformer chooses them for the task. When tokens read only the past, a global token at the start is seen by all later tokens and sees no earlier token. The next section shows why this still matters.
  • Random + window + global. BigBird (Zaheer and others, 2020) adds \(r\) random keys per query. Random links shorten the paths between tokens, as they do in a random graph. In their experiments at length 512, random keys alone and a window alone were both worse than full attention at predicting masked words. The two together were better than either, and global tokens completed the pattern.

The count for a window follows from adding up the rows. Row \(i\) of the causal window has \(i\) keys while \(i \le w\), and \(w\) keys after that. So the first \(w\) rows add up to \(w(w+1)/2\), and the other \(n - w\) rows to \((n-w)w\):

\[ \text{pairs}(w) = \sum_{i=1}^{n} \min(i, w) = \frac{w(w+1)}{2} + (n-w)\,w = w\,n - \frac{w(w-1)}{2} \]

  • \(n\) is the number of tokens and \(w\) the window width. When \(w \ge n\) the window is the whole causal mask and the count is \(n(n+1)/2\).
  • For a window read both ways with \(h = \lfloor w/2 \rfloor\) tokens on both sides the count is \((2h+1)\,n - h(h+1)\).

Worked example 1. Take \(n = 2{,}400\) (the frames of the dive, if a frame were one token) and \(w = 64\). The window computes \(64 \times 2{,}400 - 64 \times 63 / 2 = 153{,}600 - 2{,}016 = 151{,}584\) pairs. Causal attention computes \(2{,}400 \times 2{,}401 / 2 = 2{,}881{,}200\), so the window keeps 5.3%. Worked example 2. Take the dive log as sentences, \(n = 78{,}163\) GPT-2 tokens, with \(w = 4{,}096\). The window computes \(4{,}096 \times 78{,}163 - 4{,}096 \times 4{,}095 / 2 = 311{,}769{,}088\) pairs, against 3,054,766,366 for causal attention. That is 10.2%. Doubling the log to 156,326 tokens doubles the window's pairs (to about 630 million) and quadruples the full count.

This pattern works when most of what a token needs is near it, and when a few tokens pass summaries on to the rest. It breaks when an answer depends on a detail far away that no global, strided or random link reaches. One practical point: the skipped pairs only save time if the code skips them. A mask applied to a full \(n \times n\) table, as in the code below, computes all the pairs first. Child and others and Beltagy and others wrote special GPU programs for their patterns for this reason.

Common belief. Sparse attention is the same model with a cheaper calculation.

Why it fails. It changes what a token can read, so it changes what the model computes. A model trained with full attention gives different answers when its pairs are removed (the next section measures this). Longformer, the Sparse Transformer and BigBird are trained with their patterns.

Better account. A sparse pattern is a design choice that trades some reach for a cost that grows more slowly, and the model has to be trained with it.

Debug tip. Draw the mask for a small \(n\) before you trust it, as in D4, and check the number of keys in the first rows. The common slip is one place too many or too few: does the window include the token itself? In the code below, token 11 with a window of 4 reads tokens 8, 9, 10 and 11.

import numpy as np

def masks(n, w, l, g):
    i = np.arange(n)[:, None]; j = np.arange(n)[None, :]
    causal = j <= i
    window = causal & (j > i - w)                          # the last w tokens, itself included
    strided = causal & ((i - j <= l) | ((i - j) % l == 0)) # the last l tokens and the tokens l, 2l, 3l, ... back
    global_window = window | (causal & (j < g))            # window plus g global tokens at the start
    return {"full": np.ones((n, n), bool), "causal": causal, "window": window,
            "strided": strided, "global + window": global_window}

n, w, g = 2400, 64, 2
l = round(n ** 0.5)
for name, m in masks(n, w, l, g).items():
    print(f"{name:16s} {m.sum():>9,} pairs  {m.sum() / n**2:6.1%} of n x n")
print("formula for the window:", w * n - w * (w - 1) // 2)

import numpy as np
rng = np.random.default_rng(4127)
n, d = 12, 4
q, k, v = rng.normal(size=(3, n, d))

def attention(q, k, v, mask):
    s = q @ k.T / np.sqrt(d)
    s = np.where(mask, s, -np.inf)                 # skipped pairs get weight 0
    w = np.exp(s - s.max(1, keepdims=True))
    w /= w.sum(1, keepdims=True)
    return w @ v

i = np.arange(n)[:, None]; j = np.arange(n)[None, :]
window = (j <= i) & (j > i - 4)                    # the last 4 tokens
out = attention(q, k, v, window)

# the same thing as a loop that only ever touches the 4 allowed keys
loop = np.zeros_like(v)
for t in range(n):
    keys = range(max(0, t - 3), t + 1)
    s = np.array([q[t] @ k[u] / np.sqrt(d) for u in keys])
    w = np.exp(s - s.max()); w /= w.sum()
    loop[t] = sum(w[a] * v[u] for a, u in enumerate(keys))
print("pairs in the mask:", window.sum(), "of", n * (n + 1) // 2)
print("largest difference between mask and loop:", np.abs(out - loop).max())
print("token 11 reads tokens", np.flatnonzero(window[11]))

Quick quiz

A causal window of 4 over 10 tokens: how many pairs, and what share of the 55 pairs of causal attention?

\(4 \times 10 - 4 \times 3 / 2 = 34\) pairs, which is 62%. Rows 1 to 4 have 1, 2, 3 and 4 keys, and the other 6 rows have 4: \(10 + 24 = 34\).

Why does the stride in the Sparse Transformer grow like \(\sqrt{n}\)?

A row has about \(l\) keys from the window part and about \(n/l\) from the stride part. The sum \(l + n/l\) is smallest when \(l \approx \sqrt{n}\), where a row has about \(2\sqrt{n}\) keys and the total is \(O(n\sqrt{n})\).

How far information travels

Guess first. A model has a window of 3 tokens: a token reads itself and the two before it. Can token 25 in the top layer depend on token 1? If it can, how many layers does that take?

receptive field
all the input tokens that can influence one output (C2)
layer
one round of attention and MLP; stacking layers lets information be passed on (D5)

Windows stack like the filters of a convolutional network. A token receives information from about \(L(w-1)\) places back after \(L\) layers, and a global token cuts the path to two layers.

With a causal window of 3, token 25 needs 12 layers to receive information from token 1. With one global token and tokens reading both ways, 2 layers are enough. Teal tokens are the ones that can influence the coral token at the top.

Read the figure from the top. The coral token at layer \(L\) reads a few tokens of layer \(L-1\), and those tokens read a few tokens of layer \(L-2\). The teal set is the receptive field. For a causal window of width \(w\) it grows by \(w - 1\) places per layer. So token 25 reaches token 1 after \(\lceil 24 / 2 \rceil = 12\) layers. Longformer states the same rule. The top layer of an \(l\)-layer model with window \(w\) has a receptive field of \(l \times w\), as in convolutional networks. A dilated window, one with gaps, grows faster (Beltagy and others, 2020).

The other patterns cut the path. With a global token read both ways, token 25 reads the global token in layer 1. The global token has read all tokens by then, so token 25 has seen all tokens after 2 layers. The Sparse Transformer was designed for the same property. Any position reaches any other in a small constant number of steps (two, for its two-dimensional patterns), which is why a stride near \(\sqrt{n}\) is used. Worked example. Qwen3-4B has 36 layers. With a window of 4,096 tokens the largest receptive field is \(36 \times 4{,}095 = 147{,}420\) tokens. That is an upper bound on where information can come from. How much of it arrives is a question for measurement, because it has to be relayed through 36 layers.

Common belief. If the window is shorter than the text, the model cannot connect tokens that are far apart.

Why it fails. Layers relay. A token that cannot see token 1 directly can see a token that has already read it.

Better account. Stacked windows reach \(L(w-1)\) places, but a relay mixes information with other tokens' information. A global or strided link gives a direct route that has no relay.

Debug tip. When you choose a window, compute the reach \(L(w-1)\) first and compare it with the distance between a question and the facts it needs. If the reach is shorter, no choice of weights will connect them.

Quick quiz

A causal window of 5 and 8 layers: how far back can the top token get information from?

\(8 \times (5-1) = 32\) places back, so the receptive field is 33 tokens.

Why does a global token read both ways make any token reach any other in 2 layers?

In layer 1 the global token reads all tokens. In layer 2 all tokens read the global token, which now contains a summary of all of them.

Cutting a trained model's attention

Guess first. GPT-2 small was trained to see all earlier tokens. At test time you hide all pairs further apart than 128 tokens, with no retraining. Its loss on a 1,024-token logbook is 1.7 nats per token. Will the loss rise to about 2, to about 4 or to about 8?

loss
the average negative log probability of the true next token, in nats (D3)
attention sink
a token, usually the first, that receives a large share of the attention weight of many heads (D4; Xiao and others, 2023)

Sparse attention works best when the model is trained with it. If you cut a dense model's attention after training, the loss rises sharply, unless the first token stays visible.

On a 1,024-token logbook, a window of 128 raises the loss of GPT-2 small from 1.69 to 7.84 nats per token. With the first token also visible the loss is 2.58. A window of 512 plus the first token gives 1.68, the same as full attention.

The test used GPT-2 small (D3) on a logbook of 1,024 tokens. The logbook has three parts. First come the 16 invented reports, in English, with the English meaning used for the Hindi and Marathi ones. Then come the 10 events of the made-up dive log, and then lines of the log itself. Before the softmax, all pairs outside the pattern were set to minus infinity (D4). The loss was measured on the second half of the logbook, tokens 513 to 1,024. No weights were retrained. The grid shows, for the 144 heads, how much of its attention weight lies inside the window, averaged over the same tokens.

Press Window only and drag the window down. The loss climbs from 3.19 at 512 tokens to 7.84 at 128 and 16.75 at one token. Now press Window + first token. At 128 tokens the loss is 2.58 instead. The reason is in the grid. Many heads send much of their weight to the first token: 31 of the 144 put more than half of their weight on it, and the mean is 30%. The first token is a resting place for heads that have no token to look up. D4 found this for another text, and Xiao and others (2023) named it the attention sink. A window that drops the first token forces the softmax to spread this weight over other tokens, and the outputs are distorted. Keeping the first token restores most of the performance of window attention (Xiao and others, 2023).

The saving is modest for this model. A window of 256 plus the first token computes 230,272 pairs, 43.9% of the 524,800 of causal attention, and the loss is 1.99, 0.30 nats above full attention. A window of 512 plus the first token computes 393,984 pairs (75%) at the full-attention loss. Click the head L5H5 in the grid, the induction head of D4. A window of 64 keeps only 33% of its weight, and 54% with the first token. The head looks back to an earlier copy of a token, which may be far away. A task that needs the far copy loses it.

Read the result with care. It is one model, one text of 1,024 tokens, and the logbook is repetitive. A difference of 0.02 nats between 1.68 and 1.69 on one text is within what a different text could change. A model trained with its window from the start, as Longformer and the Sparse Transformer are, learns to work inside it.

Common belief. A sliding window only drops old tokens that matter little, so cutting it costs little.

Why it fails. The oldest token is the one the model uses as a resting place. Dropping it costs much more than dropping the tokens just behind it.

Better account. Keep a few first tokens (an attention sink) beside the window when you cut a trained model, or train the model with the pattern. Then measure on your own text.

Debug tip. If a model works at short lengths and produces strange text once its cache is trimmed to a window, check whether the first tokens were dropped. Compare the loss with and without them, as in the figure.

Quick quiz

In the figure, which line is higher at a window of 64, window only or window plus first token? Why?

Window only (8.66 against 2.94). With the first token visible, the weight that many heads put on it stays where the model expects it.

Why is the induction head L5H5 hurt more by a short window than most heads?

It attends to the token after an earlier copy of the current token. Copies can be far back, outside a short window.

A memory of fixed size

Guess first. The cache stores two vectors per token. Could one table of numbers of a fixed size, updated as a token arrives, replace it? How many items could a table of 16 by 16 numbers store, and what happens to the 17th?

linear attention
attention without the softmax, so that the whole past can be added up into one matrix (Katharopoulos and others, 2020)
state \(S\)
the fixed-size memory, here a matrix that a new token updates
state-space model
a recurrent model with a state \(h\) updated as \(h \leftarrow A h + B x\), such as S4 and Mamba
outer product
for vectors \(\mathbf{v}\) and \(\mathbf{k}\), the matrix \(\mathbf{v}\mathbf{k}^\top\) with entries \(v_a k_b\) (0.5)

Without the softmax, the sum over the past collapses into one matrix that a new token updates. The memory then stops growing, and what it can store is limited by its size.

A 16 by 16 matrix returns up to 16 well-separated items without error and then blurs. A window forgets the old items, and the delta rule keeps the newest item right. The keys and values are made up. The first 16 keys are orthonormal and later keys are random unit vectors.

Press Play with the sum memory chosen. While 16 or fewer items are stored, all bars are zero. Item 17 cannot have a key of its own, because a vector of 16 numbers has space for only 16 directions at right angles. From then on the bars rise, also for the items stored before. Now choose the others. The full cache stays accurate at any length, but it stores \(2 \times n \times 16\) numbers and so grows. The window keeps 128 numbers and forgets all items older than 4. The decay memory forgets gradually.

Where does the matrix come from? Take softmax-free attention for token \(i\), with a score \(\mathbf{q}_i \cdot \mathbf{k}_j\) and no softmax. The output is \(\sum_{j \le i} (\mathbf{q}_i \cdot \mathbf{k}_j)\,\mathbf{v}_j\). The number \(\mathbf{q}_i \cdot \mathbf{k}_j\) multiplies the vector \(\mathbf{v}_j\), and \((\mathbf{q}\cdot\mathbf{k})\,\mathbf{v} = \mathbf{v}\,\mathbf{k}^\top \mathbf{q}\). So the query can be pulled out of the sum:

\[ \mathbf{o}_i = \sum_{j\le i}\mathbf{v}_j\,\mathbf{k}_j^\top\,\mathbf{q}_i = S_i\,\mathbf{q}_i,\qquad S_i = S_{i-1} + \mathbf{v}_i\mathbf{k}_i^\top \]

  • \(S_i\) is the state after token \(i\): a matrix with one row per number in a value and one column per number in a key. It is the sum of the outer products of all earlier pairs.
  • Cost. One update and one read take about \(d_v d_k\) multiply-adds, whatever \(i\) is. So the total is \(O(n\,d^2)\) against \(O(n^2 d)\), and the memory is \(d_v d_k\) numbers whatever \(n\) is. Katharopoulos and others (2020) add a feature map to the queries and keys and a normaliser, and show that this form is a recurrent network.

Reading item \(i\) back with its own key gives the value plus noise from the others:

\[ S\,\mathbf{k}_i = \mathbf{v}_i + \sum_{j\ne i}(\mathbf{k}_j\!\cdot\!\mathbf{k}_i)\,\mathbf{v}_j \]

  • The sum is zero when all keys are at right angles to \(\mathbf{k}_i\), so \(d\) items can be separated. For random unit keys in \(d\) numbers the noise has a typical size of \(\sqrt{(n-1)/d}\).

Worked example with made-up numbers in two dimensions. Items: key \((1,0)\) with value \((3,1)\), key \((0,1)\) with value \((-1,2)\), key \((0.6,0.8)\) with value \((5,-4)\). After the first two items, \(S = \begin{pmatrix}3 & -1\\ 1 & 2\end{pmatrix}\). Reading with the first key gives \((3,1)\), the stored value, because the keys are at right angles. The third key overlaps both. After it, \(S = \begin{pmatrix}6 & 3\\ -1.4 & -1.2\end{pmatrix}\). Reading with the first key now gives \((6, -1.4)\) instead of \((3, 1)\), and with the third key \((6, -1.8)\) instead of \((5, -4)\). The third key has overlaps of 0.6 and 0.8 with the others, and so picks up \(0.6 \times (3,1) + 0.8 \times (-1,2) = (1, 2.2)\).

The delta rule fixes some of this. Before writing a pair, read what the matrix already predicts for the key, and write only the difference, scaled by a step size \(\eta\):

\[ S \leftarrow S + \eta\,(\mathbf{v} - S\mathbf{k})\,\mathbf{k}^\top \]

  • With \(\eta = 1\) and a key of length 1, the matrix returns \(\mathbf{v}\) for this key straight after the write. The correction is the gradient step of the next section.

In the example, the third write stores the difference \((5,-4) - S(0.6,0.8) = (5,-4) - (1,2.2) = (4,-6.2)\). Reading with the third key then gives \((5,-4)\), the stored value. Reading with the first key gives \((5.4, -2.72)\), worse than before for the first item. The delta rule makes the newest item right and pays for it with older items that overlap.

The state-space family has the same plan with a different update. A state-space model keeps a state \(\mathbf{h}\) and updates it as \(\mathbf{h}_t = A\mathbf{h}_{t-1} + B x_t\), with a read-out \(y_t = C\mathbf{h}_t\). S4 (Gu, Goel and Ré, 2021) made this fast and good at long ranges. Mamba (Gu and Dao, 2023) lets the step size, \(B\) and \(C\) depend on the current token, so the model can decide what to keep and what to forget. Its authors report linear scaling in the sequence length and about five times the throughput of transformers at inference. The decay memory in the figure, \(S \leftarrow \gamma S + \mathbf{v}\mathbf{k}^\top\), is the simplest form of such a forget factor.

The counting sets the limit. A matrix of \(d_{\text{head}}^2\) numbers can separate about \(d_{\text{head}}\) items. A head of size 128 can keep about 128 items apart however long the text is, so what it keeps of a text of 100,000 tokens is a summary. This is one reason why recent models mix the two kinds of layer. The configuration of Qwen3.6-27B has 48 linear layers and 16 full-attention layers, in blocks of three linear layers and one full layer. Its model card calls the linear layers Gated DeltaNet, a layer that combines a decay with the delta rule of this section (Yang and others, 2024). The reasons the authors chose this mix are in their own documentation, which this primer did not read.

Common belief. A memory of fixed size can remember a long text as well as a cache does, if it is trained well.

Why it fails. A cache of 100,000 tokens stores 100,000 separate keys and values. A matrix of fixed size can separate only about as many items as it has rows. Training can teach it what to keep, and it cannot make it larger.

Better account. A fixed memory trades perfect recall for a cost that does not grow. It suits tasks where a summary is enough. For a detail buried far back, a cache is safer.

Debug tip. If a model with a linear or state-space layer loses a detail from far back, check the task before the code. Looking up one planted item by its key is the hardest test for a fixed memory, and averages over long texts hide it.

import numpy as np

k = np.array([[1.0, 0.0], [0.0, 1.0], [0.6, 0.8]])      # keys of three items

def write_sum(S, key, val):
    return S + np.outer(val, key)                        # linear attention: add v k^T

def write_delta(S, key, val, eta=1.0):
    return S + eta * np.outer(val - S @ key, key)        # store only what S gets wrong

for name, write in (("sum", write_sum), ("delta", write_delta)):

import numpy as np
rng = np.random.default_rng(0)
d = 16

def recall_error(n, rule):
    # first d keys are orthonormal, later ones random unit vectors
    Q, _ = np.linalg.qr(rng.normal(size=(d, d)))
    keys = [Q[:, i] for i in range(min(n, d))]
    for _ in range(max(0, n - d)):
        x = rng.normal(size=d); keys.append(x / np.linalg.norm(x))
    vals = [(lambda x: x / np.linalg.norm(x))(rng.normal(size=d)) for _ in range(n)]
    S = np.zeros((d, d))
    for key, val in zip(keys, vals):
        S = S + np.outer(val, key) if rule == "sum" else S + np.outer(val - S @ key, key)
    return np.array([np.linalg.norm(S @ key - val) for key, val in zip(keys, vals)])

Quick quiz

A head has keys and values of 128 numbers. How many numbers does its state have, and how many does a cache of 10,000 tokens have for that head?

The state has \(128 \times 128 = 16{,}384\) numbers whatever the length. The cache has \(2 \times 10{,}000 \times 128 = 2{,}560{,}000\) numbers. The state is smaller from about 64 tokens on.

Why can the sum memory read back 16 items without error but not 17?

Reading item \(i\) gives \(\mathbf{v}_i\) plus noise \(\sum_{j\ne i} (\mathbf{k}_j\cdot\mathbf{k}_i)\mathbf{v}_j\). The noise is zero only if all other keys are at right angles to \(\mathbf{k}_i\), and a vector of 16 numbers has at most 16 directions at right angles.

Learning the memory while reading

Guess first. The update of the matrix in the last section is a fixed rule. What if the update were a gradient step, as in training, on a loss computed from the text itself? Which weights would the step change, and when would you take it?

test-time training
updating some weights while the model is used, with a loss built from the input (C3, B7)
fast weights
weights that change while the model reads, while the slow weights stay as trained
chunk
a block of tokens that is read before one update
self-supervised loss
a loss whose target is made from the input, so it needs no labels

A memory matrix updated by a gradient step is a small model trained while it reads. The step is the write, the chunk sets the schedule, and the weights return to their starting values for the next input.

With squared error and a step size of 1, one step writes a chunk of well-separated keys in full. A second pass over the same chunk then leaves W unchanged, while with the dot-product loss it doubles the write. The keys and values are made up, as in the last section.

Press Read next chunk. The coral bracket marks the chunk just read. The matrix W is the only thing that changes. Its starting value is \(W_0\), and chunk 1 is read with \(W_0\), chunk 2 with the matrix after the first update, and so on. Then try three things. First, set the chunk to 8 tokens and the step size to 1.2 with squared error, and read the loss on the second chunk (random keys appear after token 8). It goes up from 9.25 to 14.39, because a large chunk with overlapping keys needs a smaller step. Second, switch to the dot-product loss and press Chunks read twice. The write doubles, because that loss is linear in W and has no lowest point. Third, switch back to squared error with the same setting. The second pass leaves W unchanged, because W already fits.

The link to the last section is a derivation. Take a loss on one pair, \(L(W) = \tfrac12\lVert W\mathbf{k} - \mathbf{v}\rVert^2\). Its slope with respect to \(W\) is \((W\mathbf{k} - \mathbf{v})\mathbf{k}^\top\), so one gradient step of size \(\eta\) is \(W \leftarrow W + \eta(\mathbf{v} - W\mathbf{k})\mathbf{k}^\top\), the delta rule. A test-time training layer (Sun and others, 2024) makes its hidden state such a model, a linear map or a small MLP. It updates the model by a step of a self-supervised loss as the sequence is read. The update can be made on a chunk (a mini-batch) of tokens at a time, which is what the chunk slider changes.

\[ W \leftarrow W - \eta\,\frac{\partial L}{\partial W}, \qquad \Delta W_{\text{chunk}} = \eta\sum_{t\in\text{chunk}} (\mathbf{v}_t - W\mathbf{k}_t)\,\mathbf{k}_t^\top \]

  • \(W\) is the fast weight, and \(\eta\) the step size. \(\mathbf{k}_t\) and \(\mathbf{v}_t\) are a key and a target built from token \(t\) of the input.
  • With squared error the step is the sum of the delta-rule steps of the chunk, computed with the \(W\) from before the chunk. With chunk size 1 it is the delta rule of the last section.

Bridge to my project. In-Place Test-Time Training, a method from ByteDance Seed, treats the down projection of selected MLP blocks (D5) as the fast weight. My primer describes it for Qwen3-4B: six of the 36 blocks (layers 0, 6, 12, 18, 24 and 30), updated chunk by chunk with chunks of 4,096 tokens. The update has the form of the sum above with the dot-product loss: \(\Delta W = \eta \sum_t \hat{\mathbf{v}}_t \mathbf{h}_t^\top\). Here \(\mathbf{h}_t\) is the hidden vector the MLP computes anyway. The target \(\hat{\mathbf{v}}_t\) is built from the input by a short convolution and a projection. Generation never pauses: the update happens in the step that completes a chunk, and a chunk is read with the weights from before its own update. In-Place TTT keeps the ordinary attention and its KV cache. The fast weight is an extra memory in the MLP. I am porting the method to a Qwen vision-language model, so that it can adapt to an input after deployment. My primer builds it up from attention: see writing into a matrix, the target, the loss and the gradient, when the update runs and the KV cache. C3 shows the plainer relative of this idea, which changes the scale and shift of batch norm on a stream of photos.

Common belief. Test-time training means the model keeps learning from all it reads, for good.

Why it fails. The fast weights start from the same trained values for all inputs, and the saved model never changes (my primer, step by step). What the model learned from one report is gone when the next input starts.

Better account. Test-time training is a temporary memory kept in weights, for the length of one input. Analogy: a notepad that is wiped after a conversation. It breaks in one place. A person writes on a notepad, while here the rule for what to write was itself trained beforehand, so that what is written is useful for predicting the next token.

Debug tip. If the loss on the chunk rises after the update, the step is too large for the chunk. Lower \(\eta\) or the chunk size. A loss that is linear in the weights, like the one In-Place TTT uses, has no lowest point, so the step size alone decides how far W moves.

Quick quiz

Which weights change in test-time training, and when do they go back to their trained values?

Only the fast weights change (here the matrix W; in In-Place TTT the down projections of selected blocks). They start again from the trained values at the start of the next input.

Why is the chunk read with the weights from before its own update?

The update is applied after the chunk has been read. This also means a chunk cannot help to predict its own tokens, so a target that looks a few tokens ahead does not leak the answer.

Four routes side by side

Guess first. Of the four routes (full cache, sparse attention, a linear or state-space layer, test-time training), which keep a full copy of the old tokens, and which keep a summary?

route
a way to let a model read a long text: full attention, sparse attention, a fixed-size state, or a state trained while reading

A route gives up part of a full memory to lower the cost, and the routes pay in different places.

Only the full cache keeps all old tokens in full. The sparse route keeps a window and a few global tokens, the fixed-size routes keep a blurred sum or what an update rule wrote. The table uses the sizes of Qwen3-4B: 8 key-value heads of size 128. The row for linear or state-space layers is a hypothetical matrix of 128 by 128 per head, and the row for test-time training uses the down projection of Qwen3-4B.

Step through the routes. The top row of boxes is the text. Below it is what a route keeps. Raise the length and watch the table. The memory of the first row grows with \(n\). The sparse route stops growing once the window is full, and the two fixed-size rows do not change.

  • Full attention. Accurate, simple, and trained the usual way. The cost is the square of the length in time and a straight line in memory.
  • Sparse attention. A window plus global or strided links. The cost grows in a straight line or as \(n\sqrt{n}\). The model has to be trained with the pattern, and details outside it are lost.
  • Linear attention and state-space models. The memory is a matrix or a state of fixed size. The cost per token does not grow. The memory is a summary, and some models mix a few full layers into a stack of such layers.
  • Test-time training. The memory is a set of weights trained as the text is read, with a rule that was itself trained beforehand. It can be added beside attention, as In-Place TTT does, or be the hidden state of a layer.

No route is best in general. The choice depends on what a task needs from far back, and the only way to know is to test on the task. For SharkCam, a log of a 40-minute dive has two kinds of questions. "How many hammerhead events were there?" is a summary question, which suits a fixed memory. "At what second did the detector first see a milk shark?" is a lookup by time, which suits a cache. A system for the dive can use both.

Quick quiz

Which route needs a model trained with its pattern from the start, and why?

Sparse attention changes what a token can read. A model trained with full attention gives different answers when pairs are removed: the loss of GPT-2 small rose from 1.69 to 7.84 with a window of 128. The fixed-size and trained-memory routes also change the architecture, so they are trained as well.

Come back later

(D4, D5) Why can the KV cache store keys and values once and reuse them, and why does that mean a sliding window can also drop old ones?

Earlier tokens never read later ones, so their keys and values never change (the causal mask). With a window, tokens older than \(w\) are never read again by later queries, so their keys and values can be deleted from the cache.

(C3, B7) In C3 a test-time loop updated 96 of 20,874 numbers on a stream of photos, and In-Place TTT updates the down projections of six blocks. What do both leave fixed, and why is that a good idea?

Both leave most of the model fixed and update a small set of weights chosen in advance. The small set keeps the update cheap and limits how far the model can drift from what it learned, which is the worry about forgetting in B7.

(D1, D4) A Hindi report costs 117 tokens and its English meaning 23. How many times as many causal pairs does the Hindi report have?

\(117 \times 118 / 2 = 6{,}903\) against \(23 \times 24 / 2 = 276\), which is 25 times as many.
