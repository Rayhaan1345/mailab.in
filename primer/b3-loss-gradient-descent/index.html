Loss and gradient descent

A network turns its mistakes into one number, then walks downhill on it a few examples at a time.

Training a network means making one number small: the loss. This chapter covers the two losses used most, squared error for numbers and cross-entropy for classes, and shows why cross-entropy rescues a model that is confidently wrong. Then it follows gradient descent over a loss landscape with two weights. Last, it shows what changes when the gradient comes from a mini-batch: an epoch becomes many steps, the path gets noisy, and the batch size trades speed against steadiness.

The model in the landscape figures is one sigmoid neuron on the 268 spadenose sharks of A3, so the whole landscape fits on one screen. The sharks are made up: records generated from published length-weight relationships, not field data.

You will need: gradient descent and the learning rate of A2, the log loss of A3, the gradient and chain rule, cross-entropy, and B1.

What the network is asked to minimise

Guess first. A network has to predict three things about a shark: its weight in kg, whether it is an adult, and which of five species it is. Should one loss serve for all three? Think about what a good loss does when the network is badly wrong.

loss \(\ell\) and \(L\)
\(\ell\) is the loss for one example and \(L\) the average over a batch or the whole set (A2)
squared error
\((\hat{y} - y)^2\), the loss for a number
cross-entropy
\(-\ln p\) for the probability \(p\) given to the true answer (0.7)
score \(z\)
the raw output before the sigmoid or softmax
push
the slope of the loss on the output score: how hard training moves it (A3)

Pick the loss to match the output: squared error for a number, cross-entropy for a probability or a set of probabilities. For these matched pairs the push on the score is the prediction minus the label, with a factor of 2 for squared error. Training sends that difference back through the network.

Task

For Tag 4127, a juvenile, at a score of +5 the network says "adult" with probability 0.993. Cross-entropy gives a loss of 5.01 and a push of 0.99. Squared error gives a loss of 0.99 and a push of 0.013, about 75 times smaller.

Start with the first task. Tag 3305 weighs 0.228 kg, and a network that says 0.300 kg is 0.072 kg too high. The squared error is \(0.072^2 = 0.0052\) and the push is \(2 \times 0.072 = 0.144\). The loss is a parabola and the push a straight line, so a bigger mistake always gets a bigger push. For a number there is no trouble.

The one caveat for numbers is the size of the targets. A hammerhead of 53.889 kg predicted 10% too high is off by 5.389 kg, a squared error of 29.04. The same 10% miss on Tag 3305 is 0.0228 kg, a squared error of 0.0005. The big shark counts about 56,000 times more, so a fit would chase the largest animals. Scaling the target to a spread of 1, as this chapter does, keeps the numbers small but multiplies all the errors by the same factor, so the ratio stays. The usual remedy is to predict the log of the weight (A2). In logs a 10% miss costs \((\ln 1.1)^2 = 0.0091\) for a shark of any size.

The second task is the one from A3, now seen from the point of view of a network. Choose "juvenile" and move the score to +5. The loss curves are the left panel, and the pushes the right one. Cross-entropy keeps pushing with a size close to 1 as the network gets more wrong. Squared error pushes with a size that rises, peaks and then falls back to nearly 0, because the sigmoid is flat out there. Try "adult" with a score of −5 and the picture is mirrored.

The third task has five scores and softmax (0.7). The made-up scores 2.4, 1.2, 0.5, −0.4 and −1.8 give probabilities 0.655, 0.197, 0.098, 0.040 and 0.010. If the true species is the hammerhead, the loss is \(-\ln 0.040 = 3.22\), and the pushes \(p_k - y_k\) are 0.655, 0.197, 0.098, \(-0.960\) and 0.010. The true species has a negative push, so its score is raised. The others have positive pushes and fall. The five pushes add up to 0: the probability that is taken away from the wrong species is given to the right one.

A loss is also an average over many examples. Take the four sharks of section 3 at the start of section 2, \((w, b) = (-4, 2)\). Tags 3305 and 3363 are mature, and Tags 2193 and 3462 are immature. The model gives them a chance of being mature of 0.757, 0.987, 0.765 and 0.996. The probability it gives to the true answer is then 0.757, 0.987, \(1 - 0.765 = 0.235\) and \(1 - 0.996 = 0.004\). Taking \(-\ln\) of these gives 0.279, 0.014, 1.449 and 5.597, with a mean of \(L = 1.835\). Tag 3462 alone supplies 76% of the total. For all 268 sharks the mean at this start is 2.965. The loss is dominated by confident mistakes, so training attends to them first.

\[ \ell_{\text{sq}} = (\hat{y} - y)^2 \qquad \frac{\partial \ell}{\partial \hat{y}} = 2\,(\hat{y} - y) \]

\[ \ell_{\text{CE}} = -\bigl[\,y\ln p + (1-y)\ln(1-p)\,\bigr],\quad p = \sigma(z) \qquad \frac{\partial \ell}{\partial z} = p - y \]

\[ \ell_{\text{CE}} = -\sum_{k=1}^{K} y_k \ln p_k = -\ln p_t,\quad p_k = \frac{e^{z_k}}{\sum_j e^{z_j}} \qquad \frac{\partial \ell}{\partial z_k} = p_k - y_k \qquad L = \frac{1}{m}\sum_{i=1}^{m}\ell_i \]

  • \(\hat{y}\) is a predicted number and \(y\) the true one. \(p\) is a probability and \(y\) a label, 0 or 1. \(z\) is the score, and \(t\) is the number of the true class.
  • With \(K\) classes, \(y_k\) is the one-hot label: 1 for the true class and 0 for the others (A3). Only the true class's term is left in the sum, which gives \(-\ln p_t\).
  • \(L\) is the average of the single-example losses over the \(m\) examples being used. Mean squared error (MSE) is \(L\) for squared error.
Show the steps behind \(p_k - y_k\) for softmax

Write the loss with the logarithm of the sum: \(\ell = -\ln p_t = -\ln\dfrac{e^{z_t}}{\sum_j e^{z_j}} = -z_t + \ln\sum_j e^{z_j}\). Take the slope with respect to the score \(z_k\). The first term gives \(-1\) when \(k = t\) and 0 otherwise, which is \(-y_k\). The second term, by the chain rule (0.6), gives \(\dfrac{e^{z_k}}{\sum_j e^{z_j}} = p_k\). So \(\dfrac{\partial\ell}{\partial z_k} = p_k - y_k\).

For squared error through a sigmoid, \(\ell = (p - y)^2\) with \(p = \sigma(z)\). The chain rule gives \(2(p - y)\) times the slope of the sigmoid, \(p(1-p)\). The extra factor \(p(1-p)\) is the whole difference between the two losses.

Common belief. Squared error is a fine loss for any task: it only needs the output to be close to the label.

Why it fails. With a sigmoid or softmax output, the factor \(p(1-p)\) multiplies the push. When the network is confidently wrong, that factor is near 0, and the push is about 75 times smaller than cross-entropy's. In a network the push also travels back through the earlier layers (B4). A push that is small at the output is small for all the weights, including those in the first layers.

Better account. Use squared error for numbers and cross-entropy for probabilities. The next section shows the same difference as a walk across a landscape.

Debug tip. Check the loss at step 0. With \(K\) classes and a network that starts near a guess, cross-entropy should begin near \(\ln K\): 0.69 for two classes, 1.61 for five. A very different number points to a bug in the labels or the loss (B8, after Karpathy's recipe). In PyTorch, nn.CrossEntropyLoss expects raw scores and applies the softmax itself, so applying softmax first gives a wrong, flatter loss.

In practice: use the library's combined function for softmax and cross-entropy. It works from the scores and avoids \(\ln 0\). Scale a target that is a number, as the weights in this chapter are scaled, so that its loss is easy to read. Averaging the loss over the batch, and not summing it, keeps the size of the gradient about the same when the batch size changes, so a good learning rate stays good.

The last line of this printout shows why cross-entropy is the natural loss for probabilities. The product of the four probabilities, 0.00065, is the chance that the model gave to all four true answers together. The mean of \(-\ln\) is \(-\ln(0.00065)/4 = 1.835\), the same number. So minimising the mean cross-entropy makes the labels in the table as likely as possible under the model, the idea of 0.7.

Used in: the push \(p - y\) is the number that backpropagation starts from (B4). Cross-entropy over a vocabulary is the loss that trains language models (D3).

Quick quiz

A network gives probability 0.25 to the true species out of five. What is the cross-entropy, and what would a model that guesses with equal probabilities score?

\(-\ln 0.25 = 1.386\). A uniform guess gives 0.2 to the true species, so \(-\ln 0.2 = \ln 5 = 1.609\). The network is a little better than a guess.

The scores of a three-class network give probabilities (0.7, 0.2, 0.1) and the true class is the second. What are the three pushes?

\(p - y = (0.7 - 0,\; 0.2 - 1,\; 0.1 - 0) = (0.7, -0.8, 0.1)\). They add up to 0, and the true class has the only negative push.

A two-class network shows a loss of 3.0 at step 0. What does \(\ln 2\) tell you, and what could explain 3.0?

A network that guesses gives \(\ln 2 = 0.69\). A loss of 3.0 means the network starts out confidently wrong, as the start \((-4, 2)\) of section 2 does (2.965). Check the labels, the loss function and the starting weights.

The loss landscape

Guess first. A model has two dials, a weight \(w\) and a bias \(b\), and any pair has a loss. Picture the loss as a height above the \((w, b)\) plane. Suppose gradient descent starts at a place where the model is confidently wrong. Do you expect a quick slide to the valley or a slow crawl? Does it depend on which loss you use?

loss landscape
the loss drawn as a height above the plane of the weights
contour line
a curve along which the loss is the same (0.6)
valley
a low region; the lowest point is the valley floor
plateau
a wide flat region far from a valley, where the gradient is almost 0
saddle
a point where the gradient is 0 but the loss is not at a minimum

Gradient descent walks downhill on the loss landscape, and the loss function decides the landscape. For the same model and data, cross-entropy slopes into the valley from nearly all places, while squared error through a sigmoid has flat plateaus where the walk stalls.

Here is the first step by hand. For cross-entropy the gradient at \((-4, 2)\) is \((\partial L/\partial w, \partial L/\partial b) = (-0.682, -0.004)\). With \(\eta = 0.5\) the weight moves from \(-4\) to \(-4 - 0.5 \times (-0.682) = -3.659\), and the bias from 2 to 2.002. For squared error the gradient is \((-0.050, -0.062)\), a vector 8.5 times shorter, and \(w\) moves only to \(-3.975\). Both gradients lead downhill, but they differ: the squared error one is shorter and points in another direction. The reason is the factor \(p(1-p)\), which multiplies the term of a single shark. At this start the model gives almost all juveniles a probability near 1 and about a third of the adults a probability below 0.2. So \(p(1-p)\) is below 0.1 for about two sharks in three.

One shark shows the factor at work. Tag 3462 is immature, with a scaled length of \(-0.898\), and the model gives it \(p = 0.996\). Its term in the cross-entropy gradient on \(w\) is \((p - y)\,x = 0.996 \times (-0.898) = -0.895\). Its term in the squared error gradient is \(2\,(p - y)\,p(1-p)\,x = 2 \times 0.996 \times 0.0037 \times (-0.898) = -0.0066\), about 135 times smaller. The loss still sees this shark as a big mistake, and the squared error gradient hardly hears it.

The second step starts at \((-3.659, 2.002)\). The new cross-entropy gradient is \((-0.671, 0.008)\), so the weight moves to \(-3.659 + 0.5 \times 0.671 = -3.323\) and the bias to 1.998. The loss falls from 2.965 to 2.735 after the first step and to 2.511 after the second. Squared error falls from 0.568 to 0.565 and then to 0.562. The cross-entropy steps are about 0.34 long, and the squared error steps about 0.04 long, the length of the gradient times \(\eta\).

\[ \frac{\partial L_{\text{CE}}}{\partial w} = \frac{1}{m}\sum_{i=1}^{m}(p_i - y_i)\,x_i \qquad \frac{\partial L_{\text{sq}}}{\partial w} = \frac{1}{m}\sum_{i=1}^{m}2\,(p_i - y_i)\,p_i(1 - p_i)\,x_i \qquad \begin{pmatrix} w \\ b \end{pmatrix} \leftarrow \begin{pmatrix} w \\ b \end{pmatrix} - \eta\,\nabla L \]

  • \(p_i = \sigma(w x_i + b)\) is the model's probability for shark \(i\), \(y_i\) its label and \(x_i\) its scaled length. The bias slopes are the same sums with \(x_i\) left out. The first formula is derived in A3.
  • \(\nabla L\) is the vector of the two slopes (0.6). The step is \(\eta\) times its length, so a short gradient gives a short step.
  • Near the valley floor the two losses agree: their valleys are at almost the same place, \(w = 4.61\) and \(4.64\). They differ in the approach.

Common belief. Gradient descent always slides quickly to the bottom, as a ball rolls down a bowl.

Why it fails. The step is \(\eta\) times the gradient. On a plateau the gradient is almost 0, so the step is almost 0, and the walk crawls. With a squared error and sigmoid, the walk from a confidently wrong start spends 300 steps on the plateau.

Better account. The landscape is not a bowl. Its form comes from the loss and the model together, and a well-matched loss such as cross-entropy keeps a slope wherever the model is wrong. A bigger \(\eta\) can hide the problem, but it risks bouncing near the valley (A2).

In practice: you never see this picture for a full-size network, which has millions of weights. You see the loss curve, and you check it against what you know. A flat start is a warning sign: it may be a plateau, a dead unit, or a learning rate that is too small. Starting weights are small random numbers so that the start is not on a plateau (B6). Li and colleagues (2018) drew two-dimensional slices through the loss of neural networks to compare landscapes.

Why does the walk slow down near the valley floor? Near a minimum the loss along one direction looks like \(\tfrac{1}{2}k\,(w - w^{*})^{2}\), where \(k\) is the curvature (0.6) and \(w^{*}\) is the floor. A gradient step gives \(w - \eta k\,(w - w^{*})\), so the gap to the floor is multiplied by \(1 - \eta k\). Take a gap of 3 and \(k = 1\). With \(\eta = 0.5\) the gaps are 3, 1.5, 0.75, 0.375. With \(\eta = 1.5\) they are 3, \(-1.5\), 0.75, \(-0.375\): the path bounces and still shrinks. With \(\eta = 2.5\) they are 3, \(-4.5\), 6.75, \(-10.1\), and the path blows up. So \(\eta\) must stay below \(2/k\).

The cross-entropy of this chapter's neuron has a steep direction and a flat one. At the valley floor the table of curvatures has the values 0.0914 and 0.0072, as the printout below shows. The largest safe \(\eta\) is \(2/0.0914 = 22\). With \(\eta = 0.5\) the flat direction shrinks its gap by \(1 - 0.5 \times 0.0072 = 0.9964\) per step, a time constant of about 280 steps. That is why the last stretch to the floor is slow, and why a larger \(\eta\) helps here. To choose \(\eta\) on a new problem, try 0.001, 0.01, 0.1 and 1 for 100 steps apiece and keep the largest one whose loss still falls steadily.

import numpy as np, pandas as pd

d = pd.read_csv("catch.csv")
d = d[d.species == "spadenose"]  # the 268 spadenose sharks (made up)
x = ((d.length_cm - d.length_cm.mean()) / d.length_cm.std(ddof=0)).to_numpy()
y = d.mature.to_numpy().astype(float)

def gradients(w, b):
    p = 1 / (1 + np.exp(-(w * x + b)))
    ce = np.array([np.mean((p - y) * x), np.mean(p - y)])
    sq = 2 * (p - y) * p * (1 - p)  # squared error has the extra factor p (1 - p)
    return ce, np.array([np.mean(sq * x), np.mean(sq)])

for name, which in (("cross-entropy", 0), ("squared error", 1)):
    w, b = -4.0, 2.0
    print(name)
    for step in range(1, 4):
        g = gradients(w, b)[which]
        w, b = w - 0.5 * g[0], b - 0.5 * g[1]
        print(f"  step {step}: gradient ({g[0]:.3f}, {g[1]:.3f}) -> (w, b) = ({w:.3f}, {b:.3f})")

p = 1 / (1 + np.exp(-(4.61 * x + 2.48)))  # the valley floor of the cross-entropy
f = p * (1 - p)
# the table of curvatures (second slopes) of the loss
H = np.array([[np.mean(f * x * x), np.mean(f * x)], [np.mean(f * x), np.mean(f)]])
print("curvatures at the valley floor:", np.linalg.eigvalsh(H).round(4))

A network's landscape has more than one valley

A single neuron has one valley. A network with a hidden unit has more. Take the smallest network that bends: one input \(x\), one tanh hidden unit and one output, \(f(x) = w_2 \tanh(w_1 x)\), with no biases. Here it predicts the scaled weight of a spadenose shark from its scaled length, with squared error. The map below has \(w_1\) across and \(w_2\) up.

The two valleys are mirror images. After 700 steps the run from (1.5, 2) ends near (0.38, 2.70) and the run from (−1.5, 2) near (−0.39, −2.67). Both give the same curve and a loss of 0.119, and the loss keeps falling very slowly along the valley. At (0, 0) the gradient is 0, but the point is a saddle and no valley.

Press "Run 700 steps" from the starts one by one. The start at (1.5, 2) goes to the upper right valley and (−1.5, 2) crosses to the lower left one. The two end at different weights, with the same curve and the same loss. The reason is that \(\tanh\) is an odd function, so flipping the sign of both weights gives the same output. The valleys are long and curved because the product \(w_1 w_2\) is what mostly sets the slope of the curve, and many pairs have the same product. The start at (0, 0) does not move at all. The reason is in the gradient:

\[ \frac{\partial \ell}{\partial w_2} = 2\,(f - t)\,\tanh(w_1 x) \qquad \frac{\partial \ell}{\partial w_1} = 2\,(f - t)\,w_2\,\bigl(1 - \tanh^2(w_1 x)\bigr)\,x \]

  • \(t\) is the target (the scaled weight) and \(f = w_2 \tanh(w_1 x)\) the network's output. The second slope uses the chain rule through the tanh (0.6).
  • At \(w_1 = 0\) the factor \(\tanh(w_1 x)\) is 0, so the first slope is 0. At \(w_2 = 0\) the factor \(w_2\) is 0, so the second slope is 0. At the origin both vanish.

Two things follow. A bad start can be a stuck start: all weights at 0 is the classic example (B6). And weights are not unique. Two networks trained from different starts can have different weights and the same function. So comparing the weights of two training runs is not a safe way to compare the networks. At a learning rate of 0.3 or more, this narrow valley makes the path bounce from side to side and settle at a higher loss, the \(\eta < 2/k\) limit of 0.6.

Here are the two slopes for one shark. Tag 3305 has a scaled length of 0.216 and a scaled weight of 0.016. At \((w_1, w_2) = (1.5, 2)\) the hidden value is \(\tanh(1.5 \times 0.216) = 0.313\), and the output is \(f = 2 \times 0.313 = 0.627\). The error is \(f - t = 0.611\), so \(2\,(f - t) = 1.222\). The slope on \(w_2\) is \(1.222 \times 0.313 = 0.383\). The slope on \(w_1\) is \(1.222 \times 2 \times (1 - 0.313^2) \times 0.216 = 0.477\). Both are positive, so this shark asks for both weights to shrink, since the network predicts too heavy a shark. Over all 268 sharks the slopes at this point are 0.510 and 0.924.

The saddle is not a trap for starts near it. Only a start at the origin itself has a zero gradient. At \(\eta = 0.3\) a start at \((0.01, 0.01)\) leaves it and reaches a loss under 0.2 in 14 steps, while a start at \((0, 0)\) stays for ever. The gradient is small near the saddle and grows as the walk moves away, so the walk speeds up as it leaves.

import numpy as np, pandas as pd

Quick quiz

At a point the gradient is \((-0.5, 0.2)\) and \(\eta = 0.1\). Where does the next step go, starting from \((1, 1)\)?

\((1, 1) - 0.1 \times (-0.5, 0.2) = (1.05, 0.98)\). The point moves to the right and slightly down.

Why does squared error with a sigmoid output crawl from a confidently wrong start, and what fixes it?

Its gradient has the factor \(p(1-p)\), which is near 0 when the network is sure of its answer, so the step is tiny. Cross-entropy cancels that factor and keeps a slope there. A larger \(\eta\) also helps but needs tuning.

A weight is 2 away from the floor, where the curvature is \(k = 0.5\). Where is the gap after one step with \(\eta = 1.5\), and with \(\eta = 5\)?

The gap is multiplied by \(1 - \eta k\). For \(\eta = 1.5\) the factor is \(1 - 0.75 = 0.25\), so the gap becomes 0.5. For \(\eta = 5\) the factor is \(1 - 2.5 = -1.5\), so the gap becomes \(-3\): the weight jumps past the floor and ends farther away. The limit is \(2/k = 4\).

Batches and epochs

Guess first. The table has 268 spadenose sharks. One way to take a step is to compute the gradient from all 268. Another is to use only 16 of them. If you use 16 per step, how many steps does one pass through the table take? Is the gradient from 16 sharks the same as the one from 268?

A mini-batch step uses the average gradient of \(B\) examples. One epoch is \(\lceil m/B \rceil\) steps, and the order is shuffled again at the start of the next epoch.

Here is one batch with numbers. Take the model at \((w, b) = (-4, 2)\) and four sharks: Tag 3305 (41.0 cm, mature), Tag 3363 (34.2 cm, mature), Tag 2193 (40.9 cm, immature) and Tag 3462 (31.4 cm, immature). Their scaled lengths are 0.216, \(-0.573\), 0.205 and \(-0.898\). The model gives them \(p = 0.757, 0.987, 0.765, 0.996\), so \(p - y = -0.243, -0.013, 0.765, 0.996\). Multiply these by the lengths to get \(-0.053, 0.008, 0.157, -0.895\). The batch gradient on \(w\) is their average, \(-0.196\), and on \(b\) it is the average of the \(p - y\), \(0.376\). The gradient from all 268 sharks is \((-0.682, -0.004)\). The four sharks agree on the sign for \(w\) but get the bias wrong: that is noise.

Why is the batch gradient right on average? Draw one shark at random from the 268, with probability 1/268 for any given shark. The expected value of its gradient is \(\tfrac{1}{268}\sum_i g_i\), the full gradient. A batch of \(B\) is the average of \(B\) such draws, and an average of values that all have this expected value has it too. So the batch gradient is right on average. The next printout draws five batches of 16 from one shuffle. Their gradients on \(w\) are \(-1.07, -0.73, -0.58, -0.62, -0.46\), with a mean of \(-0.69\), against \(-0.68\) for all 268. The bias gradients run from \(-0.10\) to \(0.30\), and the batch with 50% mature sharks has the largest. That is the noise of the next section. Shuffling again at the start of an epoch changes which sharks share a batch. The noise then differs from one epoch to the next, and the path does not repeat one zigzag.

The last line of the printout explains the advice to shuffle. In a table sorted by length, the first 16 sharks are all immature and the last 16 are all mature. Taken in order, the first batches would push the model to call all the sharks immature, and the last batches would push it back.

\[ \theta \leftarrow \theta - \eta\,\frac{1}{|\mathcal{B}|}\sum_{i\in\mathcal{B}} \nabla \ell_i(\theta) \qquad \text{steps per epoch} = \left\lceil \frac{m}{B}\right\rceil \qquad \text{updates after } E \text{ epochs} = E\left\lceil \frac{m}{B}\right\rceil \]

  • \(\theta\) means all the weights (here \(w\) and \(b\)). \(\mathcal{B}\) is the set of examples in the current batch and \(|\mathcal{B}|\) its size, which is \(B\) except for a short last batch.
  • \(\nabla \ell_i\) is the gradient of the loss for example \(i\). The batch gradient is their average, an estimate of the gradient over all \(m\) examples.
  • \(\lceil\cdot\rceil\) rounds up. For \(B = 20\): \(\lceil 268/20 \rceil = 14\) steps, 13 full batches of 20 and a last batch of 8. After 30 epochs that is 420 updates. For \(B = 64\): 5 steps, with a last batch of 12.

Common belief. A step must use all the data, or the gradient is wrong.

Why it fails. The gradient of the average loss is the average of the single-example gradients, and a random batch gives an unbiased estimate of that average. It is noisy, but it points the right way on average. With all 268 sharks you spend 268 gradients on one step. With 16 you spend 16 per step and take 17 steps for the same cost.

Better account. A mini-batch trades accuracy for the number of steps. The gradient of a batch is cheap and approximate, so you can take many of them.

Debug tip. Shuffle. If the table is sorted, for example by species or by length, all the batches contain one kind of shark and the gradient jumps from step to step. Shuffle at the start of an epoch, and make sure that labels and inputs are shuffled together. A last batch that is smaller than the others is normal. A batch of size 1 will make some losses and normalisation layers fail.

In practice: typical batch sizes for networks are 16 to 256, limited by memory on the graphics card. Photos take much more memory than rows of a table, so a batch of photos is often smaller. Report progress in epochs, since one epoch is the same amount of data for all batch sizes. With \(B = 100\) an epoch is 3 steps, of 100, 100 and 68 sharks. Some libraries can drop the short last batch, and some losses need it kept.

Quick quiz

The table has 600 records and the batch size is 128. How many steps is an epoch, and how large is the last batch?

\(\lceil 600/128 \rceil = 5\) steps. Four full batches use 512 records, so the last batch has \(600 - 512 = 88\).

Why is the mini-batch gradient correct on average, though wrong for one batch?

An example's gradient is drawn from the table at random, and the average of the loss over the table is the average of the examples' losses. The average of many random batches is the full gradient, but one batch scatters around it.

A table sorted by length is used in order, with \(B = 16\) and no shuffling. What goes wrong in the first few batches?

The shortest sharks are all immature, so the first batches contain no mature shark. Their gradient pushes the model to call all the sharks immature. Later batches, with the longest sharks, push the other way. The path swings, and the end of an epoch is wherever the last batches left it.

Noisy steps

Guess first. You train with a batch size of 1 and with a batch size of 268, for the same 10 epochs and with the same learning rate. Which path is smoother? Which one gets to the valley first?

A mini-batch gradient is a noisy copy of the full gradient, and the noise falls like \(1/\sqrt{B}\). Small batches take many noisy steps per epoch, large batches take few steady ones, and in a fixed number of epochs small batches usually get further.

From the start (−4, 2) at \(\eta = 0.3\), after 10 epochs a batch of 16 has taken 170 steps and has a loss of about 0.25, close to the valley floor's 0.232. A batch of 268 has taken 10 steps and is still at about 1.7. The noise of the gradient halves when the batch size is multiplied by 4.

Slide the batch size from 268 down to 1. At 268 the path is a short smooth curve with only 10 dots, one per epoch, and it has barely left the start. At 16 the path is a rough line of 170 steps that reaches the valley. At 1 the path is a jagged zigzag of 2,680 steps that jitters around the valley floor, because a single shark pushes the weights hard in its own direction. The noise dots in the lower plot stop at \(B = 128\), since for \(B = 268\) the batch is the whole table and the noise is 0. Now switch the loss plot to "against steps". The big batches look good per step, since the steps are steady. But a step with 268 sharks costs 268 gradients, and a step with 16 costs 16. So the fair comparison is per epoch, as the first view shows, and in epochs the small batches win.

The dots in the lower plot show how the noise shrinks. At the valley floor the average gradient is almost 0, but single sharks disagree: the spread of one shark's contribution is \(\sigma = 0.153\). The average of \(B\) sharks has spread \(\sigma/\sqrt{B}\), times a small correction that the formula below explains. The spread is 0.076 for 4 sharks, 0.037 for 16 and 0.017 for 64. Without the correction the last two would read 0.038 and 0.019. Quadrupling the batch halves the noise. Here is why, in three lines. The \(B\) values have variance \(\sigma^2\) apiece. The variance of their sum is \(B\sigma^2\), when the draws are independent. Dividing the sum by \(B\) divides the variance by \(B^2\), so the average has variance \(\sigma^2/B\) and spread \(\sigma/\sqrt{B}\). This is the standard error of 0.7.

\[ \operatorname{Var}\!\Bigl(\frac{1}{B}\sum_{j=1}^{B} g_j\Bigr) = \frac{\sigma^{2}}{B} \qquad \text{spread of the batch gradient} \approx \frac{\sigma}{\sqrt{B}}\sqrt{\frac{m - B}{m - 1}} \]

  • \(g_j\) is the gradient contribution of one example, here \((p_j - y_j)\,x_j\) for the weight \(w\), and \(\sigma\) its spread over the table.
  • The second factor is a correction for drawing without putting back. It is close to 1 for small \(B\) and 0 for \(B = m\), where the batch is the whole table and there is no noise.
  • The formula assumes the draws are independent, which is nearly true when \(B\) is much smaller than \(m\). In the figure the dots follow the formula.

What does this noise do to the path? A step is \(\eta\) times the gradient, so noise in the gradient becomes jitter in the weight. At the valley floor and \(\eta = 0.3\), a batch of 1 moves \(w\) by a random amount of about \(0.3 \times 0.153 = 0.046\) per step. A batch of 16 moves it by \(0.3 \times 0.037 = 0.011\). The B = 1 path jumps about four times as far around the floor as the B = 16 path. Its final loss therefore varies more from one shuffle to the next. Lowering \(\eta\) late in training shrinks the jitter in proportion (B5). The printout draws 4000 random batches at four sizes and compares their spread with the formula.

Common belief. A bigger batch is always better, because its gradient is more accurate.

Why it fails. A more accurate gradient costs more per step, and gives fewer steps per epoch. After 10 epochs the full-batch run has taken 10 steps and is still near the start. The run with a batch of 16 has taken 170 and is at the valley. In one large study of image networks, batches of 2 to 32 gave the best test results (Masters and Luschi, 2018). Larger batches are still used when a graphics card runs them in parallel.

Better account. The batch size sets a trade-off: small batches make quick noisy progress, large batches make slow steady progress and use hardware better. The learning rate has to be tuned with it. Set \(B = 1\) and \(\eta = 1\) and press "Another shuffle" a few times. The path keeps jumping and the loss after 10 epochs changes from run to run, while \(B = 16\) at the same \(\eta\) settles near 0.233.

Debug tip. A jagged training loss is normal with small batches, because a step uses a different group of sharks. Do not judge a run by the loss of one batch. Measure the loss on the full table at the end of an epoch, as the figure does, or on a fixed held-out set (A4). If the loss is jagged and not trending down at the same time, lower the learning rate.

In practice: start with a batch size of 32 for a small table and a learning rate near 0.01 to 0.1, then tune. A common mistake is to add the loss over the batch and not average it. The step is then \(B\) times larger, and a learning rate that worked for one batch size diverges for another. A second one is to compare two batch sizes after the same number of steps and not the same number of epochs. Bottou, Curtis and Nocedal (2018) review why stochastic gradient methods suit large problems.

import numpy as np

rng = np.random.default_rng(0)
m = 268
length = rng.normal(39.1, 8.6, m)                     # made-up lengths, cm
x = (length - 39.1) / 8.6                             # scaled
y = (rng.uniform(size=m) < 1 / (1 + np.exp(-(4.6 * x + 2.5)))).astype(float)   # made-up labels: 1 = mature

def loss(w, b):
    p = 1 / (1 + np.exp(-(w * x + b)))
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

w, b, eta, B = -4.0, 2.0, 0.3, 16
print(f"start: loss {loss(w, b):.3f}")
for epoch in range(1, 11):
    order = rng.permutation(m)                         # shuffle again at the start of an epoch
    for start in range(0, m, B):
        idx = order[start:start + B]                   # one mini-batch (the last one may be smaller)
        p = 1 / (1 + np.exp(-(w * x[idx] + b)))
        w -= eta * np.mean((p - y[idx]) * x[idx])      # average gradient over the batch
        b -= eta * np.mean(p - y[idx])
    steps = epoch * int(np.ceil(m / B))
    print(f"epoch {epoch:2d}: {steps:3d} steps, loss {loss(w, b):.3f}, w = {w:.2f}, b = {b:.2f}")

Quick quiz

The noise of a batch gradient is 0.15 at \(B = 1\). Roughly what is it at \(B = 25\), and at \(B = 100\)?

\(0.15/\sqrt{25} = 0.03\) and \(0.15/\sqrt{100} = 0.015\). To halve the noise again, the batch has to grow by a factor of 4.

At \(\eta = 0.3\) the weight jitters by 0.011 per step with \(B = 16\). How can you halve the jitter, and what does it cost?

Make the batch 4 times larger, \(B = 64\), since the noise falls like \(1/\sqrt{B}\). That costs 4 times the gradients per step. Or halve \(\eta\) to 0.15. That costs speed, since all the steps are half as long.

Run A uses \(B = 16\) for 10 epochs and run B uses \(B = 268\) for 10 epochs. Which has taken more steps, and which has used more data?

Run A has taken 170 steps and run B only 10. Both have used the same data: 10 passes over the 268 sharks. That is why epochs are the fair measure of work.
