# Primer library

This folder contains the shared code of How AI Learns: the page shell, the styles and the Kit helper. The pages are the content. They live in the folders beside this one (`a1-what-is-a-model/`, `b1-one-neuron/`, and so on). A change here reaches all pages after one build.

`assets/kit.css` and `assets/kit.js` are generated from this folder. The `index.html` of a page is generated too, from the `page.html` beside it. Do not edit them.

## What is here

| Path | Purpose |
|---|---|
| `template.html` | The page shell of chapters and practice sets: top bar, title block, previous and next, footer. |
| `template-index.html` | The page shell of the front page. |
| `partials/` | Parts that both shells use: `head.html` (the head), `footer.html` (the footer with the theme toggle) and `scripts.html` (the script block). |
| `libs.json` | The libraries a page can load from the network (Plotly bundles, D3, KaTeX) with their pinned versions. |
| `pages.py` | Reads `page.html`, fills the template, resolves the library list. Used by `build.py`. |
| `starter/` | The files `new_chapter.py` copies to start a chapter. |
| `new_chapter.py` | Starts a new chapter folder from the starter. |
| `css/*.css` | The styles, one file per family. Source of `assets/kit.css`. |
| `kit.js` | The Kit helper: plots, controls, quiz, code blocks, navigation, theme. Source of `assets/kit.js`. |
| `build.py` | Builds all `index.html` files from their `page.html`, joins the styles, copies `kit.js`, stamps version hashes. |
| `preview.py` | Makes a noindex copy of the primer with a link back to the live version. |
| `check_styles.mjs` | Compares the computed style of all elements between two copies of the site. |
| `CHANGES-2.3.md` | Step 2.3: which components were unified, which variants were found, and which pages changed. |

## Pages: source and generated

A page is a folder with one file that you edit, `page.html`, and one that the build writes, `index.html`:

    primer/b1-one-neuron/
      page.html           the source: front matter, then the content of the page (edit this)
      index.html          generated by lib/build.py from page.html (do not edit)
      b1-one-neuron.js    the chapter script
      b1-one-neuron.css   styles of this chapter only (optional)
      data/               data of this chapter (optional)
    primer/page.html      the source of the front page, primer/index.html

`index.html` starts with a comment that says it is generated. The next build overwrites a hand edit. `page.html` is served with the site like any other file. No page links to it.

### What the template supplies

The template and its partials contain what is the same on all pages or follows from `chapters.json`:

- the doctype, charset, viewport, the title and the fonts,
- the stylesheets: KaTeX when the page lists it, `kit.css`, and `<slug>.css` when that file exists,
- the theme script, `<body data-chapter="...">` and the `main` wrapper,
- the top bar, and the title block (kicker, `h1`, subtitle),
- the previous and next placeholder (`nav#chap-nav`), the footer and the theme toggle,
- the scripts, in this order: the libraries from `libs`, `kit.js`, the `scripts` list, then `<slug>.js` when that file exists.

The rest is in `page.html`: the intro box (`tldr`), `youneed`, the contents list (`nav.toc`), the sections, the exercises, the come-back section and the references. Do not write any shell element there. The build stops with a message when a `page.html` has one.

These come from `chapters.json` and are not repeated in `page.html`: the title (also the `h1`), the chapter number, the part and its name, and the id for `data-chapter`. The folder name is the slug, and the build looks it up in `chapters.json`.

### Front matter

The front matter is a block of `key: value` lines between two lines of three dashes, at the top of `page.html`. A line that starts with `#` is a comment. A value is written as HTML, on one line (`&middot;` and `&amp;` as in the page). The build stops on an unknown key, so a typo is caught.

    ---
    description: Lists, dictionaries, classes, NumPy and a first look at PyTorch.
    subtitle: Read and write the short programs this primer uses
    libs: plotly-cartesian, katex
    kicker: Part 0 &middot; Toolkit &middot; Chapter 0.1
    ---
    <div class="tldr">
    ...the content...

| Key | Needed | Meaning |
|---|---|---|
| `description` | yes | The meta description. |
| `subtitle` | yes | The line under the title. |
| `libs` | no | The libraries to load, comma separated, from `libs.json`. All current pages list `katex`. |
| `scripts` | no | Extra scripts of this page, comma separated, loaded after `kit.js` and before `<slug>.js` (for example `treelab.js`). |
| `kind` | no | `chapter` (default), `practice` or `index`. A practice set gets `main.pset`, "Practice set 0.P" in the top bar and "Part A · Practice set" as kicker. The front page, `primer/page.html`, is `index`. |
| `kicker` | no | Replaces the line above the title. The default is `Part B · Chapter B1` (a practice set: `Part B · Practice set`). |
| `topbar_part` | no | Replaces the part name in the top bar. The default is `Part B, Neural networks` (a practice set: `Neural networks`). |
| `byline`, `og_title`, `og_description`, `og_url`, `author` | no | The front page uses them. Any page may use the `og_` keys and `author`. |

The front matter of 26 pages writes the kicker out, because the pages number their chapters in different ways. Part 0 adds "Toolkit". The chapters from B7 to E4 say "Chapter 7" where the default says "Chapter B7". The practice set of Parts E and F names both parts. The text is as it was before the template. When the kickers are made the same, delete those lines.

### Libraries

`libs.json` lists the libraries with a `version`, the `css` and `js` addresses (`{v}` is replaced by the version), and a `use` note. The versions are written there and nowhere else. The order of the entries is the order in which they load. The Plotly bundles share a `group`: a page lists at most one of them.

| Name | Loads | Use it for |
|---|---|---|
| `plotly-cartesian` | Plotly 2.35.2, cartesian bundle | 2D charts, contour, heatmap, histogram |
| `plotly-gl3d` | Plotly 2.35.2, gl3d bundle | 3D plots and basic 2D scatter |
| `plotly-full` | Plotly 2.35.2, full bundle | contour or heatmap and 3D on one page |
| `d3` | D3 7.9.0 | diagrams that are not charts |
| `katex` | KaTeX 0.16.11: stylesheet, script, auto-render | typeset maths |

To add a library, add an entry to `libs.json` in the place where it should load, then list its name in the `libs` of the pages that need it. To change a version, change it in `libs.json` and run the build. All pages that list the library follow.

### Change the shell

Edit `template.html`, `template-index.html` or a file in `partials/`, then run `python3 primer/lib/build.py`. All 47 pages change. The template is plain HTML with four tags:

- `{{name}}` puts in a value,
- `{{#if name}}...{{else}}...{{/if}}` uses the first part when the value is not empty,
- `{{#for name}}...{{.}}...{{/for}}` repeats the text for the items of a list,
- `{{> name}}` puts in `partials/name.html`.

A tag alone on its line takes the line with it. A name the build does not know is an error. Values are not read again for tags, so `{{` in a page is safe.

### Add a chapter

    python3 primer/lib/new_chapter.py b10-something

This creates `primer/b10-something/` with `page.html` (front matter and a small working example), `b10-something.js` and `b10-something.css`. It prints the entry to add to `chapters.json`. Add it (`id`, `num`, `slug`, `title`, `blurb`, `part`, and `"live": false`). Edit the three files, then run `python3 primer/lib/build.py` and open the page. The build stops with a message until the chapter is in `chapters.json`.

### The contents list stays in the content

`nav.toc` could be generated from the `h2` headings, but that would change pages. On 7 pages (0.3, 0.5, 0.6, 0.7, B5, B7, B8) the contents list uses a shorter label than the heading, and on 3 pages (0.1, 0.2, 0.8) the come-back section is not in the list. If the labels are made the same, the list can be generated, with an optional short label in the heading for the pages that want one.

### Practice sets and the front page

The six practice-set pages and the front page are generated by scripts outside this repo (`pXwork/build.py` and `build_index.py` in the working folder). They now write `page.html`, not `index.html`: front matter (`kind: practice`, or `index`) followed by the content. Run `python3 primer/lib/build.py` after them. The count of ready chapters on the front page comes from the `live` flags in `chapters.json`.

## Where CSS goes

- **Two or more pages need it:** it goes in the library, in the file of its family, as one definition. Search `css/` before you add a rule.
- **One chapter's figure needs it:** it goes in `<slug>/<slug>.css`, next to the page. The page links it right after `kit.css`. The build stamps the link. Prefix the class names with the chapter's prefix (`d3-`, `tl-`, `wk-`).
- **A page has no `<style>` element.** It has no `style=""` attribute that a utility class covers (below). Dynamic values that a script sets, and one-off sizes on SVG parts, may stay inline.
- **Colours are palette variables.** Write `var(--navy)` or `color-mix(in srgb, var(--coral) 20%, transparent)` in CSS, and `Kit.palette()` or `Kit.css("coral")` in scripts. A literal colour is allowed only for a photograph, a white figure plate, the dark terminal block of `.replay`, or a transparent fill. Dark mode comes from the tokens, so a rule needs no dark variant.
- **A page may override a library class** for its own figure, in its `<slug>.css`. The override stays in the chapter when hoisting it would restyle other pages that use the same component. `CHANGES-2.3.md` lists these under "Kept in the chapters".
- **Class names do not change.** Pages keep the names they have.
- **Order and strength.** A rule in `<slug>.css` comes after `kit.css`, so it beats a library rule of the same strength. A library rule that must beat another one in a different file needs a more specific selector. Do not depend on file order for that.
- **Two components with one name.** The library scopes the one it defines so that it cannot reach the other: `.pset .pbar` (the timer bar of the practice sets, F3 has its own `.pbar`), `table.tbl` (C2 uses a `div` called `tbl`), `span.tk` (E4 and the SVG labels of the practice sets have their own `.tk`). Do the same when a name is already taken.
- **Figures that animate are painted from script.** Do not use CSS animations or transitions for figure content.

## How to add a component

- **Check the name.** Search `css/` and the pages for `class="name"` and for `.name`. If another page uses the name for something else, scope your rule as described under "Two components with one name".
- **Pick the family file** by what the thing is: a teaching block in `20-teaching.css`, an equation or code panel in `30-math-code.css`, a part of the figure card in `40-figure.css`, a table in `50-tables.css`, a part of an SVG figure in `60-figdraw.css`, a practice-set part in `70-practice.css`.
- **Write the rule** in a section with a one-line comment above it. Write sizes the way the neighbouring rules do. Put the mobile rule in `@media (max-width: 760px)` directly under the section.
- **Run** `python3 primer/lib/build.py`.
- **Check** with `check_styles.mjs` against the previous copy of the site. Pages that do not use the new class must be identical.
- **If the component is for one chapter only**, put it in that chapter's `<slug>.css` instead.

## Utility classes

They live in `80-utilities.css`. They use `!important` where they replace an inline style, so that they win over a component rule, as the inline style did.

| Class | Effect | Replaces |
|---|---|---|
| `fs-13` | `font-size: 13px` | `style="font-size:13px"` on small SVG text |
| `mt-6`, `mt-8`, `mt-10`, `mt-12`, `mt-14` | margin above, in px | `style="margin-top:12px"` |
| `m-b4`, `m-b8` | no margin above, 4px or 8px below | `style="margin:0 0 8px"` |
| `mw-36` | `max-width: 36em` | a table that should not fill the width |
| `label-block` | `display: block`, 4px below | a label on its own line above a control |
| `tint-navy`, `tint-coral`, `tint-teal`, `tint-sand`, `tint-ink` | sets `--c` to that palette colour | `style="--c: var(--navy)"` on a legend swatch |
| `sr` | visually hidden, still read by screen readers | |
| `hide-s` | hidden below 600px | |

## Build

    python3 primer/lib/build.py            write what is stale
    python3 primer/lib/build.py --check    write no files, exit 1 if something is stale

Run the build after a change in `css/`, `kit.js`, the template, the partials or `libs.json`, after you add or edit a `page.html`, and after you change `chapters.json`. A second run has no work to do. It uses Python 3 and no other packages.

`--check` fails when an `index.html` differs from what its `page.html` would give now, so a forgotten build or a hand edit of a generated page is found. A folder that has an `index.html` but no `page.html` is a problem, and so is a `page.html` whose folder is not in `chapters.json`. The build also renders `starter/page.html` as a chapter, so the starter cannot go out of step with the template.

The build also checks the rule that a page has no `<style>` element. A page may link the library, its own `<slug>.css`, KaTeX and the Google fonts. Any other stylesheet, and any `<style>` element, is reported as a problem and makes `--check` fail.

## Version stamps

The template writes the links without a version. The build adds it, so the generated page links the library like this:

    <link rel="stylesheet" href="../assets/kit.css?v=25da757f">
    <link rel="stylesheet" href="b1-one-neuron.css?v=0c1d2e3f">
    <script src="../assets/kit.js?v=e92d596e" defer></script>

The value after `v=` is the first 8 hex digits of the sha1 of the file's content. When the file changes, the value changes, so browsers fetch the new copy. Nobody types a version number. The build stamps a chapter's own `<slug>.js` and `<slug>.css` the same way, and so it does other local scripts and styles next to a page, such as `treelab.js`. Links to other sites are left alone.

## Preview

    python3 primer/lib/preview.py OUTDIR

This runs `build.py --check`, then copies `primer/` to `OUTDIR` without `lib/` and without the `page.html` sources. In the copy only, the pages get `noindex`, a canonical link to the live page, and a small pill at the bottom right that reads "Preview v2 · open current version". `OUTDIR` is created, or replaced if it contains an earlier preview. All links in the pages are relative, so the folder can have any name, for example `primer-v2`.

## Checking that styles did not change

    python3 -m http.server 8890    # run in the folder that has the old copy of the site (primer/ inside)
    python3 -m http.server 8891    # run in the folder that has the new copy
    node primer/lib/check_styles.mjs --compare http://127.0.0.1:8890 http://127.0.0.1:8891 --jobs 4

The script needs Node 22 and Google Chrome. For three states of a page (width 1100 light, width 1100 dark, width 390) it waits 9 seconds for the figures, then records a hash of the full computed style of all elements, plus console errors. It prints the page states that differ. It blocks Google web fonts and normalises the ids that Plotly makes up, because both make two runs of one page differ. The other modes are at the top of the script: one page as JSON, snapshot a folder, diff two folders, and `--detail` for property-level differences on one page.

When one rule changes the height of an element, the computed height, `top`, `bottom` and the origins of all its ancestors change too, and so do absolutely placed elements further down the page. To find the element that was restyled, ignore `height`, `width`, `block-size`, `inline-size`, `top`, `bottom`, `left`, `right`, `perspective-origin` and `transform-origin`, and look at what is left.

## Notes

- `starter/` replaces the old `_template/` folder, which Git ignored and which therefore existed only in a working copy. A working copy may still have a `_template/` folder. The build reports it as a folder with an `index.html` and no `page.html`. Delete it.
- The practice-set pages and the primer index are generated by scripts outside this repo (see "Practice sets and the front page"). Run `build.py` after generating. Set `PRIMER_OUT=DIR` to make a practice-set generator write its page folder into `DIR` for a test run, and `PRIMER=DIR` for the index generator.
- `a5-decision-trees/treelab.js` still writes its own style element at run time (the `.tl-` classes of the tree lab). Its palette colours are `color-mix` of the palette variables.
